## 怎么用

1. **先做「第一部分 题目卷」**，一次做完一个专项（20–40 分钟），中途不要翻答案。
2. **再对「第二部分 答案与解析」**，错题在题号上打叉，回到讲义对应章节重看「原理链精讲」。
3. **二刷只做打叉的题**。三刷只看讲义附录 A（必背清单）与附录 B（易错点）。
4. 计算题不要只看懂，**必须自己动手算一遍**——看懂和算对是两件事。

## 微机原理 1–4 章 分章自测题（共 84 题）

### 第 1 章 绪论

1. **答案**：数码集合、进位规则；$N=\sum_i a_i\times r^i$；$i$ 从 0 开始（最低位 $i=0$）。　**解析**：进位计数制由"用哪些数码"和"如何进位"两个要素决定；按权展开时最低位编号为 $i=0$，逐位向高位递增，故通式即各位数码乘 $r^i$ 后求和。（来源：知识点 1）
2. **答案**：(1) $22$；(2) $14863$；(3) $4D9H$；(4) $11001B$。　**解析**：(1) $10110B=16+0+4+2+0=22$；(2) $3A0FH=3\times4096+10\times256+0\times16+15=14863$；(3) 每 4 位一组：0100|1101|1001 → 4D9H；(4) 除 2 取余：$25\div2=12$ 余 1，$12\div2=6$ 余 0，$6\div2=3$ 余 0，$3\div2=1$ 余 1，$1\div2=0$ 余 1，逆序读数得 11001B。（来源：例题 2、3、7、8）
3. **答案**：7 位（00H～7FH，共 128 个字符）；30H～39H；41H～5AH；61H～7AH；91H；0901H。　**解析**：ASCII 用 7 位编码；数字 '0'～'9' 连续排在 30H～39H，大写字母 'A'～'Z' 为 41H～5AH，小写字母 'a'～'z' 为 61H～7AH。十进制 91 的压缩 BCD 把十位、个位各占半个字节 → 91H；非压缩 BCD 每位占一个字节、高半字节补 0 → 0901H。（来源：知识点 15、16）
4. **答案**：(1) $[-Y]_补=1100\ 1011B=CBH$；(2) $[X-Y]_补=85H$；(3) $X=-70$；(4) 扩展为 16 位得 $FF85H$。　**解析**：(1) $[Y]_补=35H=0011\ 0101B$，取反得 $1100\ 1010B$，加 1 得 $1100\ 1011B=CBH$；核对 $-53=256-53=203=CBH$。(2) 竖式 $1011\ 1010B+1100\ 1011B=1\ 1000\ 0101B$，最高位进位丢弃，得 $85H$；验证 $1000\ 0101B$ 取反加 1 得 $0111\ 1011B=123$，真值 $-123$，恰为 $-70-53$。(3) $[X]_补=1011\ 1010B$ 取反得 $0100\ 0101B$，加 1 得 $0100\ 0110B=70$，故 $X=-70$。(4) $[X-Y]_补=85H$ 符号位为 1 → 高 8 位补 1，得 $FF85H$。（来源：例题 22）
5. **答案**：(1) 错，应为 $0000\ 0100B$；(2) 错，应为 $1111\ 1100B$；(3) 对；(4) 错，$1000\ 0000B$ 的真值是 $-128$。　**解析**：(1) 正数补码同原码，$1111\ 1100B$ 是 $[-4]_补$。(2) $1000\ 0100B$ 是 $[-4]_原$，补码应为取反加一得到的 $1111\ 1100B$。(3) $+4$ 的原码 $0000\ 0100B$ 连符号位一起取反即 $1111\ 1011B$，故该说法正确。(4) 0 在补码中只有 $0000\ 0000B$ 一个码，$1000\ 0000B$ 用来表示 $-128$。（来源：例 1.9、知识点 21）
6. **答案**：真值 $-123$；扩展为 16 位写 $FF85H$；若补 0 得 $0085H$，真值变为 $+133$。　**解析**：$[X]_补=85H=1000\ 0101B$，取反加一得 $0111\ 1011B=123$，加负号即 $-123$；负数扩展时符号位为 1，高 8 位必须补 1，故为 $FF85H$。若错误地补 0 得 $0085H$，按补码读为正数 $128+5=+133$，与 $-123$ 不等——这正是负数扩展必须补 1 的原因。（来源：例题 22、方法 15）
7. **答案**：(1) 错；(2) 错；(3) 对。　**解析**：(1) 冯·诺依曼（普林斯顿）结构是程序总线与数据总线**混合编址**，程序与数据共用同一存储空间和总线；独立编址的是哈佛结构。(2) 所有外设都应通过 I/O 接口电路才能连到 CPU，不能直接接到 CPU 上。(3) 1 Word = 2 Byte = 16 bit，字为 16 位，即两个字节。（来源：知识点 26、27、34、11）

### 第 2 章 8086 系统结构

9. **答案**：16；16（D0~D15）；20（A0~A19）；1MB；6；2。　**解析**：8086 是 16 位微处理器，数据总线 16 位、地址总线 20 位，直接寻址空间 $2^{20}=1{,}048{,}576$ 字节 $=1$MB；指令队列 6 字节，队列空出 2 个及以上字节时 BIU 自动预取。
10. **答案**：9 个；状态标志是 CF、PF、AF、ZF、SF、OF 共 6 个；控制标志是 TF、IF、DF 共 3 个。　**解析**：$6+3=9$ 与有效标志个数吻合；状态标志反映运算结果的特征，控制标志用于控制 CPU 的操作。

## 专项 A：指令判错题（共 34 题）

### 一、找错并改正

1. **答案**：两个操作数不能同时为存储器单元。**解析**：错在哪——源、目的都带方括号，都是存储器操作数。为什么错——8086 一条指令的机器码只能对一个存储单元寻址，内存到内存的直接传送缺少中间暂存，没有这样的指令（而且两个操作数都没表明字节还是字）。正确写法——经寄存器中转：`MOV AX,[2000H]` 再把 `MOV [3000H],AX`，用 AX 同时明确宽度与方向。（例3.27）

2. **答案**：立即数不能作目的操作数。**解析**：错在哪——2000H 不带方括号，是写在指令里的常数（立即数）。为什么错——立即数固化在代码区、由 BIU 预取，是只读的指令内容，没有可写入的操作数地址；而目的操作数必须是可写入的位置。正确写法——要存入偏移 2000H 的单元就写 `MOV [2000H],AX`，`[2000H]` 才是地址（直接寻址，默认段 DS）。

3. **答案**：不能把立即数直接送段寄存器。**解析**：错在哪——源是立即数 2000H、目的是段寄存器 DS。为什么错——8086 规定立即数不能直接送段寄存器（段寄存器受系统管理），`SEG` 运算符的结果同样要中转。正确写法——经通用寄存器中转：`MOV AX,2000H` + `MOV DS,AX`。

4. **答案**：CS 不能作目的操作数。**解析**：错在哪——目的是代码段寄存器 CS。为什么错——CS 的内容由系统管理，程序不能任意改写（`MOV CS,AX`、`POP CS` 均非法）；DS、ES、SS 可作目的，但源不能是立即数。正确写法——要改变 CS:IP 只能用控制转移指令，如段间转移 `JMP FAR PTR 标号`。

5. **答案**：源与目的长度不一致。**解析**：错在哪——源 AH 是 8 位，目的 CX 是 16 位。为什么错——CX 虽然装得下这 8 位数据，但汇编程序无法判定该放进 CH 还是 CL，生成不了确定的指令编码；源与目的长度必须一致。正确写法——`MOV CL,AH`（或 `MOV CH,AH`）。（例3.4）

6. **答案**：立即数超出目标宽度。**解析**：错在哪——300=12CH，超出 AL 能表示的 8 位范围。为什么错——立即数的编码只有 8 位，必须放得进目标寄存器（按无符号解释即 00H~FFH，按补码解释即 −128~+127），放不下时汇编报"立即数超出范围"。正确写法——改用 16 位寄存器 `MOV AX,300`（若必须用 AL，则把数值限制在 0~255 内）。

7. **答案**：直接端口寻址的端口号超过 255。**解析**：错在哪——310H>FFH，却写成直接端口形式。为什么错——端口号直接编码在指令的 8 位立即数字段里，该字段只有 8 位，只能寻址 00H~FFH 共 256 个端口。正确写法——先 `MOV DX,310H`，再 `IN AL,DX`（DX 是唯一可用的端口号寄存器，间接端口寻址范围 0000H~FFFFH）。（例3.32）

8. **答案**：段超越前缀用错。**解析**：错在哪——`[BP]` 的默认段寄存器是 SS，加上 `DS:` 把默认段改成了 DS。为什么错——含 BP 的存储器操作数默认用 SS 提供基地址（BP 用于访问堆栈区数据），写成 `DS:[BP]` 后取到的是数据段中同一偏移处的内容，不是堆栈里的参数。正确写法——不写前缀 `MOV AX,[BP]`，此时 $\text{PA}=16\times\text{SS}+\text{BP}$；只有确实要访问 DS 段数据时才写 `DS:[BP]`。

9. **答案**：寻址方式书写非法（同类寄存器同现）。**解析**：错在哪——[ ] 内同时出现 BX 和 BP。为什么错——BX、BP 同属基址类，SI、DI 同属变址类，地址生成通路只提供"1 个基址＋1 个变址＋位移量"三个分量，同类寄存器没有第二条通路。正确写法——合法组合只有 BX+SI、BX+DI、BP+SI、BP+DI，如 `MOV AX,[BX+SI]`（若含 BP 则默认段为 SS）。

10. **答案**：需要类型说明符而未写。**解析**：错在哪——源是常数 0、目的是 `[BX]`，双方都没有表明是字节还是字。为什么错——汇编程序无法确定传送位数，生成不了确定的指令编码。正确写法——加 PTR 说明：`MOV BYTE PTR [BX],0`（一个字节单元）或 `MOV WORD PTR [BX],0`（一个字单元）；也可把一方换成寄存器来明确宽度。

11. **答案**：移位次数大于 1 却直接写在指令里。**解析**：错在哪——计数值 3 直接写在指令中。为什么错——移位指令只在次数为 1 时允许直接写（如 `SAL AH,1`），次数大于 1 时必须先把次数送入 CL；移位次数最多 31（00011111B）。正确写法——`MOV CL,3` + `SHL DI,CL`。（例3.70）

12. **答案**：字除法前没有清 DX。**解析**：错在哪——执行 DIV BX（字操作）前未处理 DX。为什么错——字除法的被除数在 DX:AX 中，位宽必须是除数位宽的两倍；DX 中残留的旧值会被当作被除数的高 16 位，商随之全错（还可能因商超范围触发除法错中断）。正确写法——在 DIV BX 前先 `XOR DX,DX`（或 `MOV DX,0`）；字节除法则对应先清 AH。

13. **答案**：条件转移类型用错。**解析**：错在哪——无符号数比较却用了 JG。为什么错——JG 是带符号比较指令（条件 SF=OF 且 ZF=0），而 A/B 组（JA/JAE/JB/JBE）依据 CF、ZF，才对应无符号数的大小关系；源件例3.89 中同一组数据用 JAE 与 JL 会得出相反结论，说明必须先分清数据类型再选指令。正确写法——`JA BIG`（CF=0 且 ZF=0，即高于）。

14. **答案**：条件转移超出短转移范围。**解析**：错在哪——目的标号距本条指令约 300 字节。为什么错——8086 全部条件转移都是段内短转移，8 位偏移量经符号扩展后与 IP 相加，距离只能是 −128~+127 字节，300 字节超出范围，汇编报错。正确写法——写成"条件转移跳过一条 JMP"：

    ```asm
          JNC  SKIP
          JMP  FAR_LABEL
    SKIP: ...
    ```

15. **答案**：SEGMENT 与 ENDS 的段名不一致。**解析**：错在哪——段以 `DATA SEGMENT` 开始，却以 `DATAS ENDS` 结束。为什么错——段定义伪指令必须成对出现且段名一致，段名即该段的段基址，名字不符就无法配对成段。正确写法——把结束语句改为 `DATA ENDS`。

16. **答案**：堆栈不平衡，RET 取不到正确返回地址。**解析**：错在哪——过程内 `PUSH BX` 之后没有对应的 `POP BX`。为什么错——PUSH 先 $SP\leftarrow SP-2$ 再入栈，POP 先出栈再 $SP\leftarrow SP+2$，只有配对 SP 才回到原位；SP 比进入过程时低 2，RET 从栈顶弹出的就不是 CALL 压入的返回地址，而是 BX 的旧值，程序跳到错误地址。正确写法——RET 前补 `POP BX`，使 PUSH/POP 成对。

17. **答案**：循环前没有把循环次数送入 CX。**解析**：错在哪——程序只设置了指针 BX，从未给 CX 赋值。为什么错——`LOOP 标号` 执行时先 $CX\leftarrow CX-1$，再判 $CX\ne0$ 则转移，循环次数由 CX 初值决定，BX 只是数据指针；CX 未赋值时按残留值循环，若 CX=0 则先减 1 得 0FFFFH，变成 65535 次的超长循环。正确写法——循环体前加 `MOV CX,100`。

18. **答案**：IP 不能作操作数。**解析**：错在哪——把 IP 当作传送指令的目的操作数。为什么错——IP 不能用传送类指令直接读写，只能由转移、调用、返回、中断等指令由硬件自动修改（CS、IP 都不能作目的操作数）。正确写法——`JMP NEXT`（段内转移，只改 IP，CS 不变）。

19. **答案**：两个存储器单元不能直接交换。**解析**：错在哪——XCHG 的两个操作数都是存储器操作数。为什么错——XCHG 可用组合只有寄存器↔寄存器、寄存器↔存储单元；一条指令不能同时寻址两个存储单元，而且段寄存器不能作 XCHG 的操作数。正确写法——经寄存器中转：

    ```asm
    MOV  AX,[BX]
    XCHG AX,[SI]
    MOV  [BX],AX
    ```

20. **答案**：源与目的长度不一致。**解析**：错在哪——源 BX 是 16 位，目的 AL 是 8 位。为什么错——ADD 要求源与目的类型一致（都字节或都字），长度不符时汇编程序无法确定运算位数。正确写法——`ADD AL,BL`（都字节）或 `ADD AX,BX`（都字）。

### 三、多错并改

29. **答案**：三处错误：①`MOV DS,DATA`——立即数不能直接送段寄存器；②`MOV AL,X`——X 由 DW 定义为 16 位的字变量，目的 AL 只有 8 位，长度不一致；③`MOV [BX],0`——源与目的都未表明宽度，需要类型说明符。**解析**：①DATA 是段名，汇编时成为 16 位常数，属立即数，必须经通用寄存器中转，改为 `MOV AX,DATA` + `MOV DS,AX`；顺带记住 ASSUME 只向汇编程序描述段寄存器与段的对应关系、用来确定默认段，**不给段寄存器赋值**，所以这两条装入指令必须写。②源 16 位、目的 8 位，汇编程序无法生成确定编码，若取 X 的内容应改为 `MOV AX,X`。③改为 `MOV BYTE PTR [BX],0` 或 `MOV WORD PTR [BX],0`。（BX 作为指针应在使用前赋偏移值，属程序完整性，不计入本题的三类指令错误。）

30. **答案**：三处错误：①`POP CS`——CS 不能作目的操作数；②`MOV 2000H,AX`——立即数不能作目的操作数；③`PUSH BX` 后没有 `POP BX`——堆栈不平衡，RET 取到错误返回地址。**解析**：①CS 由系统管理，MOV CS,AX 与 POP CS 均非法，若要恢复现场应改为 `POP AX`（与前面的 PUSH AX 配对）。②2000H 不带方括号是常数，没有可写入的地址；要存入偏移 2000H 的单元应写 `MOV [2000H],AX`（直接寻址，默认段 DS）。③SP 比进入过程时低 2，RET 弹出的不是 CALL 压入的返回地址而是 BX 的旧值，程序跳飞；RET 前必须补 `POP BX`。

31. **答案**：三处错误：①第一条 `DIV BX` 前未清 DX；②带符号除法前用 `XOR AH,AH` 加宽被除数；③第三条 `DIV BL` 的商会超出 AL 范围。**解析**：①字除法的被除数是 DX:AX，必须是除数位宽的两倍，DX 中的残留旧值被当成被除数高位，商随之全错；应在 DIV BX 前加 `XOR DX,DX`（字节除法对应先清 AH）。②IDIV 前不能把高位置 0：对负数会改变数值（−38 会变成 +218），必须用 `CBW` 把 AL 的符号位扩展到 AH（D7=1 则 AH=FFH、AX=FFDAH=−38）。（例3.62）③7A86H÷04H 的商为 1EA1H=7841，超出 AL 能存放的范围（FFH=255），会自动产生除法错中断，等效于除数为 0，商和余数都不确定——除数不为 0 也可能出错；改正为字除法，让商落进 AX：

    ```asm
    MOV  AX,7A86H
    XOR  DX,DX
    MOV  BX,0004H
    DIV  BX          ；AX←商 1EA1H，DX←余数 0002H
    ```

    （例3.61）

32. **答案**：三处错误：①`ROR [SI],1` 未说明操作数类型；②`AND [BX],[SI]` 两个操作数同时为存储器；③`[BX+SI+DI]` 地址分量非法。**解析**：①存储器操作数必须用 `BYTE PTR`/`WORD PTR` 说明宽度，否则无法确定按字节还是按字移位，改为 `ROR WORD PTR [SI],1`（例3.73）。②逻辑指令同样要求"两个操作数不能同时为存储器"，一条指令只能对一个存储单元寻址，须经寄存器中转，如 `MOV AL,[SI]` + `AND [BX],AL`。③地址生成通路只能容纳"1 个基址＋1 个变址＋位移量"三个分量，三个寄存器分量非法（SI 与 DI 同属变址类也不能同现），改为 `MOV AL,[BX+SI]` 之类。

33. **答案**：三处错误：①带符号数比较用了 `JA`；②`JC FAR_SEG` 超出短转移范围；③同一符号 COUNT 二次 EQU。**解析**：①JA 是无符号比较指令（CF=0 且 ZF=0），对带符号数会给出与真实大小相反的结论（源件例3.89 中同一组数据 JAE 与 JL 结论相反）；应改用有符号组 `JG`（SF=OF 且 ZF=0）。②条件转移全部是段内短转移，距离只能是 −128~+127 字节，约 200 字节超范围，汇编报错；应写成"条件转移跳过一条 JMP"：

    ```asm
          JNC  SKIP
          JMP  FAR_SEG
    SKIP: ...
    ```

    ③EQU 汇编期直接替代，同一符号不能重复定义，只保留一条定义或改用别的符号名。

34. **答案**：三处错误：①`MOV AX,ES[BX]` 段超越前缀漏写冒号；②`LOOP AGAIN` 前从未给 CX 赋循环次数；③`END` 的位置错。**解析**：①段超越前缀必须写成"段寄存器名＋冒号"即 `ES:[BX]`，改写后 $\text{PA}=16\times\text{ES}+\text{BX}$（不加前缀时 [BX] 默认段为 DS）。②`LOOP AGAIN` 先 $CX\leftarrow CX-1$ 再判 $CX\ne0$ 转移，循环次数由 CX 初值决定，CX=0 时会先减成 0FFFFH 变成超长循环；循环前须加 `MOV CX,次数`。③END 是汇编终止标记，MASM 遇到 END 即停止汇编，写在 `CODE ENDS` 之前会使段定义不配对；END 应单独一行放在源程序最后（即 `CODE ENDS` 之后），需要时写成 `END 启动入口标号`。

## 专项 B：计算题（第 1–2 章）（共 28 题）

### 一、填空题

1. **答案**：（1）22　（2）14863　（3）B4D9H　（4）491
**解析**：
- （1）位权从 $2^0$ 起：$1\times2^4+0\times2^3+1\times2^2+1\times2^1+0\times2^0=16+0+4+2+0=22$。
- （2）A = 10、F = 15：$3\times16^3=3\times4096=12288$；$10\times16^2=10\times256=2560$；$0\times16=0$；$15\times1=15$；合计 $12288+2560+0+15=14863$。
- （3）从 LSB 起每 4 位一组：1011|0100|1101|1001 → B|4|D|9，得 B4D9H（只做分组查表，不做算术）。
- （4）$7\times8^2+5\times8^1+3\times8^0=448+40+3=491$。

2. **答案**：（1）4 个；T1、T2、T3、T4　（2）200；800　（3）T3；等待周期 Tw；$4T+n\times T_w$
**解析**：（1）总线周期是 CPU 读写一次存储器或 I/O 端口的时间，至少包括 T1、T2、T3、T4 共 4 个时钟周期。（2）$T=1/f=1/(5\times10^6)=0.2\times10^{-6}$ s = 200 ns，$4T=4\times200=800$ ns。（3）CPU 在 T3 上升沿检测 READY，为低则在 T3 后插入一个 Tw，此后每个 Tw 上升沿继续检测，直到 READY = 1 才进 T4 完成传送；故总时长 = $4T+n\times T_w$（n ≥ 0）。

3. **答案**：（1）8；2；16　（2）16；运算器；数据总线　（3）1024；65536
**解析**：1 Byte = 8 bit；1 Word = 16 bit = 2 Byte。字长决定计算机一次可处理的二进制位数，取决于运算器、通用寄存器和数据总线的位数（8086 三者都是 16 位，故为 16 位机）。1KB = $2^{10}$ B = 1024 B；64KB = 64 × 1024 B = 65536 B。

4. **答案**：（1）91H　（2）0901H　（3）0011 0010 0111B　（4）958
**解析**：BCD 码按 4 位一组**逐位替换**，不能当成一个二进制数整体换算。（1）9→1001、1→0001 → 1001 0001B = 91H。（2）非压缩 BCD 用 8 位表示 1 位十进制数字，高 4 位为 0：9→09H、1→01H → 0901H。（3）3→0011、2→0010、7→0111 → 0011 0010 0111B。（4）1001|0101|1000 → 9|5|8 = 958。

5. **答案**：（1）7；128　（2）41H；61H；20H　（3）39H

### 一、填空题

1. **答案**：累加器（8 位操作用 AL、16 位操作用 AX）；字节乘法：被乘数 AL、积送 AX（AH 高 8 位、AL 低 8 位）；字乘法：被乘数 AX、积送 DX:AX（DX 高 16 位、AX 低 16 位）；字节除法：被除数在 AX、商送 AL、余数送 AH；字除法：被除数在 DX:AX、商送 AX、余数送 DX。　**解析**：乘法/除法只写出一个源操作数，另一个操作数与结果位置由操作码隐含规定（隐含寻址）；除法的被除数位宽必须是除数位宽的两倍，商才一定放得进低半部分寄存器。源操作数可为寄存器或存储单元，不能用立即数。

4. **答案**：次数为 1 时直接写在指令中（如 SAL AH,1）；次数大于 1 时必须先把次数送入 CL（MOV CL,03H 后 SHL DI,CL）；最大 31（00011111B）；CF 由最后一次移出的位决定；SAL 与 SHL 功能完全相同；无符号数用 SHR，带符号数用 SAR。　**解析**：左移方向无符号数与有符号数没有区别，故 SAL、SHL 机器码与行为相同；右移方向 SHR 最高位补 0（负数会被变成正数），SAR 保持符号位不变，故带符号数除 2^n 只能用 SAR。

(1) 段内（近）调用时 CS 与过程同段，已是正确值、无需保存，故只压 IP 共 2 字节；返址＝CALL 指令首地址＋指令长度=1050H+3=1053H；入口＝取指后（已指向下一条指令）的 IP+DISP=1053H+1234H=2287H，若误用首地址 1050H 相加就会算错。RET 是逆过程：弹 1 个字→IP、SP+2，SP 与栈都恢复初始状态。
(2) 段间（远）调用要跨段，必须同时保存 32 位逻辑地址 CS:IP 共 4 字节，且**先压 CS 再压 IP**：所以低地址 004CH 放的是后压入的 IP=205FH、高地址 004EH 放的是先压入的 CS=1000H。远返回按后进先出：先弹 IP 再弹 CS，SP 依次 004CH→004EH→0050H，恰好复原。
(3) 4 个字的参数共 8 字节；RET n 的 n 是弹出返回地址后再从堆栈弹出的字节数（即 SP 再加 n），且必须为偶数 → 写 RET 8，使 SP 指向参数入栈前的位置，避免返回后 SP 指向废弃参数。

30. **答案**：(1) EA=BX=0200H；PA=16×1000H+0200H=10000H+0200H=10200H；低字 (10200H)=31F4H→IP，高字 (10202H)=5200H→CS → 过程入口 CS:IP=5200H:31F4H。(2) 返址=3000H+2=3002H；SP=0080H−2=007EH，CS=1000H 入栈（(2000:007EH)=00H、(2000:007FH)=10H）；SP=007EH−2=007CH，IP=3002H 入栈（(2000:007CH)=02H、(2000:007DH)=30H）。(3) RET：SP=007CH+2=007EH 弹 IP=3002H，再 SP=007EH+2=0080H 弹 CS=1000H → 回到 1000H:3002H，SP 复原为 0080H。(4) 换成 JMP DWORD PTR [BX] 后 CS←5200H、IP←31F4H，转到 5200H:31F4H，但**不压栈**，SP 仍为 0080H，也没有返址可返回。　**解析**：段间间接调用的操作数是存储器中连续存放的双字（4 字节），取值规则与段间间接转移相同：**低地址字→IP、高地址字（物理地址+2）→CS**。
(1) [BX] 不含 BP，默认段 DS：EA=0200H、PA=10200H；低字 31F4H 送 IP，高字 5200H 送 CS。
(2) CALL 的第一步是返址入栈：远调用先 SP−2 压 CS、再 SP−2 压 IP，故栈中低地址 007CH 是后压入的 IP=3002H、高地址 007EH 是先压入的 CS=1000H。
(3) 远过程 RET 按后进先出弹出：先 IP 后 CS，每弹一个字 SP+2，SP 由 007CH 经 007EH 回到 0080H，程序从断点 1000H:3002H 继续执行。
(4) CALL 与 JMP 的差别有两点：① CALL 多出"保存返址"这一步（为在子程序结束后能回到调用处，过程内必须配 RET），JMP 只改 CS:IP、不保存返址；② CALL 的寻址方式比 JMP 少一种——没有段内短调用。

## 专项 D：程序分析与编程题（共 22 题）

### 一、程序阅读题

1. **答案**：程序只做数据传送与"取地址、取长度"，不修改任何存储单元的内容（除寄存器外无副作用），最后用 4CH 功能调用返回 DOS。
　（1）功能：把数据段中若干变量的地址、长度与内容取入寄存器，随后返回 DOS。

　（2）各项数值：

| 项目 | 值 | 依据 |
|---|---|---|
| `COUNT` | 0005H | `$` 在处理到该行时等于 5（LIST 占偏移 0000H~0004H），5−0=5 |
| `LIST+1` 单元 | 26H | LIST+1 存的是 38，38=2×16+6=26H |
| `V1` 的偏移区间 | 0005H~0006H | LIST 占 0~4 共 5 字节，DW 占 2 字节 |
| `V1` 两个字节的内容 | 0005H=34H、0006H=12H | 字数据低字节存低地址（小端） |
| BX | 0005H | `OFFSET V1` 取段内偏移 |
| AL | 41H | V2（偏移 0007H）处是 `'A'`；`DB 'AB'` 按书写顺序存放，首字符在低地址 |
| AH | 42H | V2+1（偏移 0008H）处是 `'B'` |
| CX | 0005H | COUNT 是 EQU 符号常数，汇编期已直接替换成 5 |
| DX | 0064H | `SIZE V3`=LENGTH×TYPE=50×2=100=64H |

　（3）关键指令注释：
　· `MOV AX,DATA`：把数据段段基址送入通用寄存器 AX 中转（段寄存器不能直接接收立即数或段名）。
　· `MOV DS,AX`：真正把数据段基址装入 DS，使变量寻址的默认段正确（ASSUME 只声明、不装载）。
　· `MOV BX,OFFSET V1`：BX←V1 在数据段内的偏移地址 0005H。
　· `MOV AL,V2`：AL←V2 处的 1 个字节 41H（'A'）。
　· `MOV DX,SIZE V3`：DX←V3 占用的总字节数 50×2=100。
　· `MOV AX,4C00H`：AH=4CH（DOS 结束程序功能号）、AL=00H（返回码），为下一条 `INT 21H` 准备参数。

2. **答案**：程序对 ARY1（20 个字节）与 ARY2（10 个字节）分别求和，结果按低字节在前写入 SUM1、SUM2。
　（1）功能：用同一个 `SUM` 子程序分两次对两个字节数组求和，把 16 位和以"低字节在前"存入指定的两个单元。
　`SUM` 的入口参数：SI=数组首地址、CX=元素个数、BX=结果单元首地址；出口结果：`[BX]`=和的低 8 位、`[BX+1]`=进位累加值（高 8 位）。参数全部通过寄存器传递。

　（2）第一次调用：ARY1 的 20 个元素均为 200=0C8H，20×200=4000=0FA0H。每满 256 由 CF 进 1 并由 `ADC AH,0` 并入 AH，故循环结束时 AL=A0H、AH=0FH → `[SUM1]=A0H`、`[SUM1+1]=0FH`。核对：0FH×256+A0H=15×256+160=4000 ✓。
　此时 SI 已从 ARY1 首址（0000H）前移 20 次 → SI=0014H（正好是 ARY2 的首址）；CX 被 `LOOP` 减到 0。
　第二次调用：ARY2 的 10 个元素均为 200，10×200=2000=07D0H → `[SUM2]=D0H`、`[SUM2+1]=07H`。核对：07H×256+D0H=7×256+208=2000 ✓。

　（3）关键指令注释：
　· `XOR AL,AL`：既把累加器 AL 清零，又同时把 CF 清 0，保证第一次 `ADC` 不会多加 1。
　· `ADC AL,[SI]`：AL←AL+[SI]+CF，把本字节累加进低 8 位，溢出部分由 CF 带出。
　· `ADC AH,0`：把上一次字节加产生的进位累加进高字节 AH（进位传递的关键一条）。
　· `LOOP LOOP1`：CX←CX−1，CX≠0 则回到 LOOP1，循环执行 CX 次（计数循环）。
　· `MOV [BX+1],AH`：把高 8 位存入结果单元第二个字节，与"低字节在前"的约定对应。
　用 `XOR AL,AL` 而不用 `MOV AL,0`：`MOV` 不影响标志位，AL 清零后 CF 仍是上一条指令留下的值（可能为 1），第一次 `ADC AL,[SI]` 就会多加 1，和偏大；`XOR` 在清零的同时把 CF 清 0，一条指令办两件事。

3. **答案**：子程序把从键盘逐个键入的十进制数字（回车结束）按"乘 10 累加"折算成一个二进制数存入 BX。
　（1）功能：逐个键入十进制数字，用 $R_k=R_{k-1}\times10+d_k$ 把十进制数转成二进制数存入 BX。
　它是**条件循环**：循环次数由键入内容决定，不由 CX 决定。出口条件有三个：读到回车符 0DH；`SUB AL,30H` 后小于 0（非数字字符）；`CMP AL,9`／`JG` 成立（大于 9 的非数字字符）。

　（2）键入过程的 BX 值：

| 键入 | AL 的变化 | 累加式 | BX |
|---|---|---|---|
| `3` | 33H→03H | 0×10+3 | 0003H |
| `5` | 35H→05H | 3×10+5 | 0023H (=35) |
| `8` | 38H→08H | 35×10+8 | 0166H (=358) |
| 回车 | — | JE EXIT 成立 | 0166H（不再改变） |

　核对：0166H=1×256+6×16+6=256+96+6=358 ✓。

　（3）关键指令注释：
　· `MOV AH,1`／`INT 21H`：DOS 1 号功能，等待键入一个字符，键值送 AL 并回显在屏幕上。
　· `CMP AL,0DH`／`JE EXIT`：与回车符比较，相等（ZF=1）则结束输入——循环的结束判断。
　· `SUB AL,30H`：把数字字符的 ASCII 码（30H~39H）减 30H，得到数字值 0~9。
　· `CBW`：把 AL 中的数字符号扩展成 AX 中的字，**顺带清掉 AH 里残留的功能号 01H**。
　· `MOV CX,10`／`MUL CX`：DX:AX←AX×10，即"已累加值×10"。
　· `ADD BX,AX`：BX←已累加值×10＋新数字，完成一次递推。
　`CBW` 不能省：调用 1 号功能后 AH 里还留着功能号 01H，若不扩展就把 AX 当被乘数，`MUL CX` 会算成 (01xxH)×10，结果全错；`CBW` 用 AL 的符号位填满 AH，使 AX=0000H~0009H。

4. **答案**：程序显示提示串，读入一个 0~9 的数字，用查表法取出它的平方值存入 AL。
　（1）功能：显示提示后键入一位数字字符，截出数字值作下标，到 TABLE 表中取出对应平方值存入 AL。
　屏幕显示：先显示 `Please input a number(0~9):`，其中 0DH 使光标回车、0AH 换行，`'$'`（24H）是 9 号功能的终止标志、本身不显示；随后 1 号功能把键入的 `'5'` 回显出来。结果 25 只是存入 AL，**程序并未把它显示出来**。

　（2）键入 `'5'` 后的各值：

| 时刻 | 值 | 说明 |
|---|---|---|
| `AND AL,0FH` 之前 AL | 35H | '5' 的 ASCII 码 |
| `AND AL,0FH` 之后 AL | 05H | 截出低 4 位即数字值，作表内下标 |
| `ADD BX,AX` 之前 BX | 0000H | TABLE 是段内第一个变量，`OFFSET TABLE`=0000H |
| `ADD BX,AX` 之前 AX | 0005H | 必须先 `MOV AH,0` 把 8 位数字值扩成 16 位 |
| `ADD BX,AX` 之后 BX | 0005H | 表头地址＋下标＝目标单元地址 |
| `MOV AL,[BX]` 之后 AL | 19H（=25） | TABLE 中第 5 项是 25 |

　若删掉 `MOV AH,0`：AH 里还残留 1 号功能的功能号 01H，AX 变成 0105H，`ADD BX,AX` 得到 TABLE+0105H，访问到数组之外很远的单元，取回一个与平方无关的随机字节。

　（3）关键指令注释：
　· `AND AL,0FH`：按位与 0FH 只保留低 4 位，把 ASCII 码 30H~39H 变成数字值 0~9。
　· `MOV BX,OFFSET TABLE`：BX←平方表的首地址（段内偏移，此处为 0000H）。
　· `MOV AH,0`：把 AL 中的数字值扩成 16 位（同时清掉 AH 中残留的功能号）。
　· `ADD BX,AX`：表头地址＋下标＝第 i 项的实际地址（AX 必须是 16 位，才能与 BX 相加）。
　· `MOV AL,[BX]`：按算出的地址取出 1 个字节，即该数字的平方值。
　不能写成 `ADD BX,AL`：BX 是 16 位、AL 是 8 位，两个操作数长度不一致，指令非法（汇编器直接报错），故必须先用 `MOV AH,0` 把下标扩成 16 位。

5. **答案**：子程序把 BX 中的 16 位二进制数按每 4 位一组转成十六进制 ASCII 码，在屏幕上依次显示 4 个字符。
　（1）功能：用循环左移每次把 BX 的一个十六进制位（4 位）挪到低 4 位，转成 ASCII 码后用 DOS 2 号功能显示。
　屏幕最后显示 4 个字符：`9`、`A`、`7`、`F`，即 **9A7F**。

　（2）4 次循环的取值（入口 BX=9A7FH）：

| 次序 | `ROL BX,CL` 后 BX | `MOV AL,BL` 后 AL | `AND AL,0FH` 后 AL | 送 DL 的字符 |
|---|---|---|---|---|
| 1 | A7F9H | F9H | 09H | '9'（39H） |
| 2 | 7F9AH | 9AH | 0AH | 'A'（41H） |
| 3 | F9A7H | A7H | 07H | '7'（37H） |
| 4 | 9A7FH | 7FH | 0FH | 'F'（46H） |

　第 1、3 行的数字 0~9 加 30H 后得 39H、37H，都小于 3AH，`JL DISP` 成立直接显示；第 2、4 行的 0AH、0FH 加 30H 后得 3AH、3FH，不小于 3AH，再 `ADD AL,7H` 得到 41H、46H，即 'A'、'F'。
　子程序返回时 BX 仍是 **9A7FH**：`ROL` 共循环左移 4×4=16 位，等于把 BX 转回原位，源数没有被破坏。

　（3）关键指令注释：
　· `ROL BX,CL`：BX 循环左移 4 位，把最高 4 位挪到最低 4 位；用循环左移而不是逻辑左移，才能移完 16 位后原数复原。
　· `AND AL,0FH`：只取低 4 位，得到一个十六进制数字值 0~15。
　· `CMP AL,3AH`／`JL DISP`：与 3AH 比较，小于 3AH（数字 0~9）直接显示；否则是 0AH~0FH，需要再修正。
　· `ADD AL,7H`：把 3AH~3FH 平移到 41H~46H，得到 'A'~'F'。
　· `DEC CH`／`JNZ ROTATE`：CH 是大循环计数，减 1 后非 0 就继续——这里不能用 `LOOP`，因为 CL 已被用作移位位数（`MOV CL,4`）的专用寄存器。

6. **答案**：子程序把 AX 中的 16 位二进制数逐次除以 1000、100、10 取商，拼成 4 位压缩 BCD 数。
　（1）功能：用"除法取商与余"逐位求出千、百、十、个位十进制数字，再拼成 4 位压缩 BCD 数送回 AX。
　`CMP AX,9999`／`JBE TRAN`：先做范围检查，只有 AX≤9999 时才能用 4 位 BCD 表示；超过 9999 就不转换、直接返回（单分支结构）。

　（2）入口 AX=9346（2482H）的执行过程：

| 执行到 | DX / AX 的值 | 说明 |
|---|---|---|
| `SUB DX,DX` 之后 | DX=0000H | 字除前清被除数高 16 位 |
| `DIV CX`（除数 1000）之后 | AX=9、DX=346 | 字除：商在 AX、余在 DX |
| 第一次 `XCHG AX,DX` 之后 | AX=346、DX=9 | 商（千位）留在 DX |
| 第一次 `SHL DX,CL` 之后 | DX=0090H | 千位移到高 4 位 |
| `DIV CL`（除数 100）后 `ADD DL,AL` | DX=0093H | 346÷100 商 3 余 46，商拼入 DL 低 4 位 |
| 第二次 `SHL DX,CL` 之后 | DX=0930H | 已拼好的两位整体左移 4 位 |
| `XCHG AL,AH`／`SUB AH,AH` 之后 | AX=002EH（46） | 余数 46 作为下一次的被除数 |
| `DIV CL`（除数 10）后 `ADD DL,AL` | DX=0934H | 46÷10 商 4 余 6，十位拼入 |
| 第三次 `SHL DX,CL` 后 `ADD DL,AH` | DX=9346H | 个位 6 拼入最低 4 位 |
| `MOV AX,DX` 之后 | AX=9346H | 出口结果 |

　核对：9×1000+3×100+4×10+6=9346 ✓（注意入口是十进制 9346，出口是"看起来同样是 9346"的压缩 BCD 数 9346H）。

　（3）关键指令注释：
　· `SUB DX,DX`：字除法把 DX:AX 整体作被除数，必须先把 DX 清零，否则高 16 位是随机/旧值，商错甚至除法溢出。
　· 第一条 `DIV CX`（除数为字）：被除数 DX:AX、商在 AX、余在 DX。
　· 两条 `DIV CL`（除数为字节）：被除数 AX、商在 AL、余在 AH。
　· `XCHG AL,AH`／`SUB AH,AH`：把余数换到 AL，并把 AH 清 0，使 AX 恰好等于余数，为下一次字节除准备干净的 16 位被除数。
　三次 `SHL DX,CL` 前都重写 `MOV CL,4`：这三次左移分别是"千位入位后、百位入位后、十位入位后"的移位，中间夹着 `MOV CL,100`、`MOV CL,10` 等指令已经把 CL 改成了别的值，移位位数必须是 4，所以每次都要重新置 `MOV CL,4`。

7. **答案**：程序把 BUF 起的 17 个字符按 ASCII 码分成 5 段，统计数字字符、大写字母与其它字符的个数。
　（1）功能：逐个取字符，用逐级比较把 ASCII 码划成 5 段（<30H／30H~39H／3AH~40H／41H~5AH／>5AH）实现多分支，分别统计数字（DH）、大写字母（DL）与其它字符的个数，结果存入 NUM 起的 3 个单元。
　`COUNT=$−BUF`=3+5+3+5+1=**17**；DH 记数字个数、DL 记大写字母个数，其它字符数由"总数−数字−字母"算出。

　（2）统计结果：`NUM`=04H（4）、`NUM+1`=08H（8）、`NUM+2`=05H（5），4+8+5=17 ✓。
　各字符的走向（按 BUF 中的存放顺序 `+ 3 6 P R I N T a b c 2 A 0 C H #`）：

| 字符 | ASCII | 判定路径 | 归类 |
|---|---|---|---|
| `'3'` | 33H | ≥30H，≤39H → `INC DH` | 数字 |
| `'6'` | 36H | 同上 | 数字 |
| `'2'` | 32H | 同上 | 数字 |
| `'0'` | 30H | 同上 | 数字 |
| `'P'` | 50H | >39H 转 ABC；≥41H 且 ≤5AH → `INC DL` | 字母 |
| `'R'`、`'I'`、`'N'`、`'T'` | 52H、49H、4EH、54H | 同 'P' | 字母（共 5 个） |
| `'A'`、`'C'`、`'H'` | 41H、43H、48H | 同 'P' | 字母（共 3 个） |
| `'a'`、`'b'`、`'c'` | 61H~63H | >39H 转 ABC；≥41H 但 >5AH → `JG NEXT` | 其它 |
| `'+'` | 2BH | <30H → `JL NEXT` | 其它 |
| `'#'` | 23H | <30H → `JL NEXT` | 其它 |

　· `SUB DX,DX`：一条指令把 DX 清零，DH、DL 同时成为两个 0 计数器。

　`COUNT=($−LIST)/2=10/2=5`；外层循环轮数=COUNT−1=**4**；第 k 轮内层比较 5−k 次，即 4、3、2、1，总比较次数=4+3+2+1=**10** 次。

　（3）关键指令注释：
　· `MOV DX,CX`：把本轮内层应有的比较次数备份到 DX（内层 `LOOP` 会把 CX 减到 0）。
　· `MOV BX,0`：每轮内层都从数组头开始比较，指针必须重新清零。
　· `JAE NOCHG`：无符号比较，前一个元素≥后一个元素时不交换（用 CF 判），从而得到降序。
　· `XCHG AX,LIST[BX+2]`／`MOV LIST[BX],AX`：借 AX 中转完成两个字单元的交换，使大数在前。
　· `ADD BX,2`：元素是 DW（字），指针每次加 2 指向下一个元素（只 `INC BX` 会把字拆成两个字节）。
　· `MOV CX,DX`：内层结束时恢复外层计数，否则 CX 已是 0，外层只跑一轮。

10. **答案**：程序用 BIOS 键盘中断读一个键，判断是否为 Y/N 并显示不同提示串，再演示 1 号与 2 号功能。

　· 按 `Y`（59H）：第一次比较 ZF=1 → `JE YES`，DX 指向 MSG1，显示 `You pressed Y` 并回车换行。
　· 按 `N`（4EH）：第一次比较不相等，第二次相等 → 同样转向 YES，显示 `You pressed Y`（源件的 Y/N 判定就归到同一分支）。

　（3）关键指令注释：
　· `MOV AH,0`／`INT 16H`：BIOS 键盘 0 号功能，等待读入一个字符，出口 AL=ASCII 码、AH=扫描码（b7=0 表示压下、b7=1 表示松开）。
　· `CMP AL,'Y'`／`JE YES`：比较键值，相等则转去显示 MSG1。
　· `MOV AH,1`／`INT 16H`／`JZ NONE`：1 号功能查询缓冲区但不等待，ZF=1 表示缓冲区空、AL/AH 无效，必须跳过取键动作。
　· `MOV AH,2`／`INT 16H`／`MOV BL,AL`：2 号功能把键盘状态字节 KB_Flag 送 AL，每一位对应一个特殊功能键，为 1 表示该键按下；此处只把它保存到 BL。
　1 号功能处不判 ZF 就直接用 AL：ZF=1（无键按下）时 AL、AH 里根本没有有效键值，会把无意义的旧内容当按键处理，出现随机分支。

### 三、程序填空题

17. **答案**：
　（1）`CLC`　　　（2）`ADC AL,A2[BX]`　　　（3）`ADC AL,A2[BX]`　　　（4）`JNC STOP`

　为什么非补这几条：
　· （1）`CLC`：清进位标志 CF。低字节相加也用 `ADC`，若不先清 CF，第一次相加会把上一条指令遗留的 CF（可能为 1）加进去，结果偏大 1。
　· （2）`ADC AL,A2[BX]`：AL←AL+A2[BX]+CF，完成低字节相加并把进位送进 CF。BX 是统一地址指针，A1[BX] 与 A2[BX] 天然按"低字节在前"对齐。
　· （3）`ADC AL,A2[BX]`：高字节必须同样用 `ADC`，才能带上低字节产生的进位；若写成 `ADD`，进位在跨字节处丢失，和变小。
　· （4）`JNC STOP`：判最后一次（高字节）加法的进位。无进位（CF=0）则跳过写进位字节；有进位则顺序执行 `INC BX`（BX 由 1 变 2）与 `MOV SUM[BX],01H`，把进位存到 SUM+2。漏写则无论有没有进位都会往 SUM+2 写 1，还可能覆盖无关单元。

　数值验算：
　· 低字节：56H+4FH=86+79=165=A5H，未超过 255，CF=0 → SUM[0]=A5H。
　· 高字节：78H+9AH=120+154=274=112H，低 8 位 12H、CF=1 → SUM[1]=12H；`JNC` 不成立 → SUM[2]=01H。
　· 结果为 0112A5H=70309；核对：7856H=30806、9A4FH=39503，30806+39503=70309 ✓。

18. **答案**：
　（1）`COUNT-1`　　　（2）`JGE NOCHG`　　　（3）`ADD BX,2`　　　（4）`MOV CX,DX`

　为什么非补这几条：
　· （1）`COUNT-1`：冒泡排序每轮至少把一个元素送到最终位置，最后一个元素自动到位，n 个元素只需 n−1 轮。`COUNT=($−LIST)/2=10/2=5`，故外层次数为 4。
　· （2）`JGE NOCHG`：数组是**有符号数**，必须用有符号比较（看 SF 与 OF）。要求"大数在前"（降序），当 AX≥下一个元素时不交换，否则交换。**不能填 `JAE`**：`JAE` 按无符号比较（只看 CF），−12 的补码 FFF4H 最高位为 1，按无符号会被当成 65524，比 24 还"大"，排序结果完全错误。
　· （3）`ADD BX,2`：元素是 DW（字），指针每轮要跳过 2 字节指向下一个字；写成 `INC BX` 会把一个字拆成两个字节比较。
　· （4）`MOV CX,DX`：内层 `LOOP` 已把 CX 减到 0，必须先恢复外层计数再执行外层 `LOOP`；不恢复则外层只跑一轮。

　按填空后的程序走查（降序）：第一轮 −12 与 7 交换 → `7,-12,-19,8,-24`；−12≥−19 不换；−19 与 8 交换 → `7,-12,8,-19,-24`；−19≥−24 不换。第二轮 → `7,8,-12,-19,-24`。第三轮 → `8,7,-12,-19,-24`。第四轮 8≥7 不换。最终 **8, 7, −12, −19, −24**；比较次数 4+3+2+1=10 次 ✓。

TABLE DB  0,1,4,9,16,25,36,49,64,81          ; 0~9 的平方表
MSG   DB  'Please input a number(0~9):$'     ; 9 号功能显示的提示串，以 '$' 结尾

      STAPN DB  100 DUP(?)                   ; 100 字节栈区
TOP   EQU  LENGTH STAPN                      ; TOP=100（栈区最高地址加 1）
STACK ENDS
CODE  SEGMENT
MAIN  PROC FAR
      ASSUME CS:CODE,DS:DATA,SS:STACK
START:MOV  AX,STACK
      MOV  SS,AX
      MOV  SP,TOP                            ; 堆栈初始化：SS:SP
      PUSH DS                                ; 此时 DS 仍是 PSP 段地址
      SUB  AX,AX
      PUSH AX                                ; 压入 0000H，凑成返回 DOS 的远返回地址
      MOV  AX,DATA
      MOV  DS,AX                             ; DS←数据段基址（ASSUME 不装载）
      MOV  DX,OFFSET MSG                     ; 9 号功能入口：DS:DX=串首地址
      MOV  AH,9
      INT  21H                               ; 显示提示串（'$' 不显示）
      MOV  AH,1
      INT  21H                               ; 1 号功能：等待键入一个字符，AL=ASCII 码并回显
      AND  AL,0FH                            ; 30H~39H 的低 4 位就是数字值 0~9
      MOV  AH,0                              ; 扩成 16 位索引，同时清掉 AH 里的功能号
      MOV  BX,OFFSET TABLE                   ; BX←平方表首地址
      ADD  BX,AX                             ; 表头地址＋下标
      MOV  AL,[BX]                           ; 查表得平方值 0~81
      MOV  DH,AL                             ; 先把平方值暂存到 DH（见下方说明：2 号功能会破坏 AL）
      MOV  DL,0DH                            ; 先回车换行，让结果显示在新的一行
      MOV  AH,2
      INT  21H
      MOV  DL,0AH
      MOV  AH,2
      INT  21H
      MOV  AL,DH                             ; 取回平方值（此刻 AH 里是上一次的功能号 02H，不能直接用）
      MOV  AH,0                              ; 8 位除法的被除数是 AX，先清 AH
      MOV  BL,10
      DIV  BL                                ; AL=商(十位)、AH=余数(个位)
      XCHG AH,AL                             ; AH=十位、AL=个位
      ADD  AX,3030H                          ; 一条指令把两个字节都变成 ASCII 码
      MOV  CX,AX
      MOV  DL,CH                             ; 先显示十位
      MOV  AH,2
      INT  21H
      MOV  DL,CL                             ; 再显示个位
      MOV  AH,2
      INT  21H

MAIN  ENDP
CODE  ENDS
      END  MAIN

　逐段说明：
　· **段定义与堆栈**：数据段放平方表与提示串；堆栈段用 `STAPN DB 100 DUP(?)` 开 100 字节栈区，`TOP EQU LENGTH STAPN` 取 DUP 的重复次数 100 作 SP 初值（PUSH 先减 2 再存，SP 必须指向栈区最高地址加 1）。
　· **返回 DOS 的准备**：`PUSH DS`／`SUB AX,AX`／`PUSH AX` 必须在 DS 被改成数据段基址之前完成，栈中形成 [PSP 段址, 0000H]，末尾 `RET` 转到 PSP:0000 的 `INT 20H`。
　· **输入**：9 号功能显示提示（串尾必须有 `'$'`，它是唯一的终止标志）；1 号功能等待键入并回显。
　· **查表**：`AND AL,0FH` 截出数字值 → `MOV AH,0` 扩成 16 位 → `MOV BX,OFFSET TABLE` 取表头 → `ADD BX,AX` 形成项地址 → `MOV AL,[BX]` 取平方值。四步缺一不可：不 `AND` 会拿 35H 当下标；不 `MOV AH,0` 则 AX 高字节残留功能号 01H，地址错；`ADD BX,AX` 必须 16 位与 16 位相加（`ADD BX,AL` 长度不一致，非法）。
　· **输出**：平方值 0~81 是二进制数，除以 10 一次得到十位（商）与个位（余数），`+3030H` 变成两位 ASCII 码后分两次用 2 号功能显示；DIV 前必须先清 AH。
　· **为什么查表后要 `MOV DH,AL` 暂存**：本程序在查表与除法之间插了两次 `INT 21H` 的 2 号功能调用。课件把 2 号功能的出口参数记为"无"，但真实 DOS 会把 **AL 置为最后输出的那个字符**（这里是 0AH），如果仍拿 AL 当被除数，无论键入几都会算成 $0AH \div 0AH$、显示 "10"。所以跨中断调用要保存的寄存器必须显式暂存——用 DH（本程序只用到 DL 输出，DH 空闲）。同理，若把两次回车换行挪到"平方值算完并转成 ASCII 之后"再输出，也能避开这个坑。

　运行示例（下划线表示键入内容）：

```

49
```

　· **0AH 缓冲区结构**：三个部分依次是"容量字节（用户预置 50）／计数字节（DOS 写实际键入字符数，回车不计入）／字符区（从 +2 偏移起依 ASCII 码存放）"。容量字节必须由用户先写好，写成 `DB ?` 则容量是随机值，输入行为不可预期；计数字节不能省，否则字符区整体前移错位。
　· **统计循环**：`MOV CL,BUFF+1` 把"实际键入字符数"作循环次数，用 `DEC CX`／`JNZ` 实现计数循环；指针 SI 每轮 +1。ASCII 分段与源件例 4.37 一致：<30H 其它、30H~39H 数字、3AH~40H 其它、41H~5AH 字母、>5AH 其它。空串（只按回车）时用 `CMP CX,0`／`JE` 保护，避免 `DEC CX` 由 0 变 FFFFH 造成超长循环。
　· **显示**：三个统计值先存入 NUM 起的单元（因为 `DISP2` 会破坏 DX），再逐个用 `DISP2` 转成两位十进制 ASCII 码显示，中间用 2 号功能显示一个空格分隔。

　运行示例（下划线表示键入内容）：

```
Input a string:
04 08 05
```
　输入 `+36PRINTabc2A0CH#`（共 17 个字符，容量 50 足够，第 2 字节被 DOS 写入 11H=17）：数字 `3`、`6`、`2`、`0` 共 4 个；大写字母 `P`、`R`、`I`、`N`、`T`、`A`、`C`、`H` 共 8 个；其它 `+`、`a`、`b`、`c`、`#` 共 17−4−8=5 个。
