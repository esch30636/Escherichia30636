## 知识点详解

### 知识点 1：中断源

**定义**：引起中断的原因或能发出中断请求的来源称为中断源（Interrupt source）。8086 有两类中断源：1）外部中断（硬件中断），从不可屏蔽中断引脚 NMI 和可屏蔽中断引脚 INTR 引入；2）内部中断（软件中断），是为解决 CPU 运行过程中出现的一些意外事件或便于程序调试而设置的。

**理解**：中断源是对所有能使 CPU 暂停当前程序、转去执行中断服务程序的原因或请求来源的总称。8086 按请求的产生位置分类：一类产生于 CPU 芯片外部，经 NMI、INTR 两个引脚传入；一类产生于 CPU 内部，包括执行指令时出现的异常条件（除数为 0 或商溢出、OF=1）和专门的中断指令（INT n、INT 3、单步）。分类标准是请求信号的来源位置，即芯片外部还是内部。

**作用**：8086 中断系统的总入口概念，位于中断系统知识体系的顶层。外部中断、内部中断及其下属各中断类型均以它为分类依据，是后续中断向量表、中断优先级等知识点的前置概念。

---

### 知识点 2：外部中断（硬件中断）

**定义**：通过 CPU 的 NMI 引脚和 INTR 引脚引入的中断，亦称硬件中断。分为不可屏蔽中断和可屏蔽中断两类。

- 不可屏蔽中断：连接到 NMI 引脚，不受中断标志 IF 的影响，用于处理较紧急的情况，如存储器或 I/O 校验错、掉电、协处理器异常中断请求等。
- 可屏蔽中断：连到 CPU 的 INTR 引脚，IF=1 时才允许响应；可由 8259A 来管理外部多种屏蔽中断。8259A 的输入引脚 IR0~IR7 可引入 8 级中断：时钟、键盘、串行通信口 COM1 和 COM2、硬盘、软盘、打印机。经芯片内部判别后，将优先级高的中断请求信号送到 INT 引脚，它连接 CPU 的 INTR 引起中断请求。

**理解**：外部中断的共同点是请求信号均来自 CPU 芯片外部、经专用引脚传入。两类外部中断的差别在于能否被程序屏蔽：NMI 不受 IF 控制，请求到来必然被响应，故用于掉电、校验错等必须处理的事件；INTR 受 IF 控制，IF=0 时 CPU 不响应 INTR 上的请求。8259A 是可编程中断控制器，将 8 路外设请求（IR0~IR7）汇总并判别优先级后，由一条 INT 线接到 CPU 的 INTR 引脚统一提出请求，解决外设中断源多于 CPU 引脚的问题。

**作用**：与内部中断并列构成 8086 的两大类中断源。可屏蔽中断部分是第 8 章 8259A 芯片、中断嵌套内容的基础；不可屏蔽中断的类型号（n=2）是中断向量表例题的已知条件之一。

---

### 知识点 3：内部中断（软件中断）

**定义**：为解决 CPU 运行过程中出现的一些意外事件或便于程序调试而设置的中断，亦称软件中断。8086 的内部中断包括：除法错中断、单步中断、溢出中断 INTO、软件中断指令 INT n、断点中断 INT 3。

**理解**：内部中断的请求来源在 CPU 内部，产生方式有两种：一是执行指令时检测到异常条件（除法运算除数为 0 或商超出寄存器容纳范围、TF=1、OF=1 且执行 INTO）；二是执行到专门的中断指令（INT n、INT 3）。内部中断不依赖任何外部引脚信号。

**作用**：与外部中断并列构成 8086 的两大类中断源。内部中断是程序动态排错（单步、断点）和系统功能调用（通过 INT n 调用 DOS、BIOS 服务）的机制基础。

---

### 知识点 4：除法错中断

**定义**：执行除法运算指令时，若除数为 0 或商超过了结果寄存器能容纳的范围，则产生除法错中断（教材标准定义中其类型号为 0）。

**理解**：除法指令执行时存在两种错误条件：除数为 0；或商数值过大，超出目的寄存器可表示的数值范围。任一条件成立，CPU 自动产生除法错中断，无需任何外部请求信号，也不受 IF 标志控制。

**作用**：内部中断的一种，用于捕获除法运算的致命错误。在 8086 中断优先级次序中属于最高级（与 INT n、INTO 同一优先级）。

---

### 知识点 5：单步中断

**定义**：单步标志 TF 置 1 后，每条指令执行完即产生单步中断。其结果是将 CPU 的内部寄存器和有关存储器的内容显示出来，便于跟踪程序的执行过程，实现动态排错。

**理解**：TF 是 FLAGS 寄存器中的一个标志位。TF=1 时，CPU 每执行完一条指令就产生一次单步中断，转入服务程序显示寄存器与内存内容；返回后再执行下一条指令，如此逐条观察程序的执行过程。运行机制为固定循环：执行一条指令 → 产生单步中断 → 服务程序显示 CPU 状态 → 返回 → 执行下一条指令。

8086 没有直接使 TF 置 1 或清 0 的指令，需用堆栈中转。使 TF 置 1 的程序段：

```
PUSHF          ; 标志寄存器FLAGS入栈
POP    AX      ; AX←FLAGS内容
OR     AX,0100H ; 使AX（即标志寄存器内容）的D8=1，其余位不变
PUSH   AX      ; AX入栈
POPF           ; FLAGS寄存器←AX
```

用类似方法将标志寄存器内容与 FEFFH 相与（`AND AX, 0FEFFH`），可使 TF 清 0，从而禁止单步中断。

**作用**：内部中断的一种，是程序调试工具。其优先级在 8086 中断系统中最低。

---

### 知识点 6：溢出中断 INTO

**定义**：溢出标志 OF=1 时，溢出中断指令 INTO 产生中断类型号为 4 的溢出中断；若 OF=0，不会产生中断。

**理解**：INTO 是一条条件中断指令。执行 INTO 时先检查 OF 标志：OF=1 则产生类型号 4 的中断；OF=0 则不产生中断，顺序执行下一条指令。因此带符号数加、减指令后应安排一条 INTO 指令，一旦运算溢出就能及时向 CPU 提出中断请求，CPU 响应中断后进行相应处理。典型用法：

```
主程序：                溢出中断服务：
       SUB  AX, BX     INTOSERV:
       INTO            ……
       ……              IRET
```

**作用**：内部中断的一种，用于带符号数算术运算结果的溢出检测。

---

### 知识点 7：软件中断指令 INT n

**定义**：产生类型号为 n（n=0~255）的软件中断的指令，可以安排在程序的任何位置。第 4 章讲到的 DOS 系统服务和 BIOS 服务都是以这种方式调用的。

**理解**：INT n 执行时直接产生类型号为 n 的中断，不需要外部信号，也不受 IF 标志限制。n 的取值范围 0~255，对应 8086 的 256 类中断。用户程序中的 `INT 21H`（DOS 功能调用）、`INT 10H`（BIOS 显示服务）等都是执行这条指令，通过中断向量表转入相应的系统服务程序。

**作用**：内部中断的一种，是用户程序调用 DOS、BIOS 系统服务的机制基础；在 8086 中断优先级中与除法错、INTO 同为最高级。

---

### 知识点 8：断点中断 INT 3

**定义**：程序运行到断点时便产生中断，像单步中断一样，查看各寄存器和有关存储单元的内容。断点可设在程序任何地方并可设多个，设置方法是插入一条 INT 3 指令。利用断点中断可以调试一段程序，比单步中断的调试速度快得多。

**理解**：调试程序在目标程序的指定位置插入 INT 3 指令（教材标准定义中 INT 3 为单字节指令，类型号为 3）。程序执行到该指令时产生断点中断，转入调试程序查看寄存器与内存内容。与单步中断逐条指令停下不同，断点中断只在预先设定的位置停下，不需每条指令都中断，因此调试速度更快。

**作用**：内部中断的一种，与单步中断并列的程序调试工具，用于分段快速检查程序状态。

---

### 知识点 9：中断向量

**定义**：中断向量 = 中断服务程序的入口地址 = 中断服务程序的第一条指令的首地址。中断调用与 CALL 子程序不同，是段间调用，入口地址包括段地址和有效地址（偏移地址），故 1 个中断向量包括 4 个字节：偏移地址（IP 部分）放在低地址，段地址（CS 部分）放在高地址。

**理解**：中断向量由两个 16 位分量组成：段基址（对应 CS）与偏移地址（对应 IP），共 4 字节。在内存中存放顺序固定：低地址字单元放偏移地址，高地址字单元放段地址。CPU 响应中断时把这两个分量分别送入 IP 和 CS，即得到中断服务程序的执行起点。

**作用**：中断向量表的基本组成单元；CPU 响应中断时寻址中断服务程序的直接依据。

---

### 知识点 10：中断向量表

**定义**：保存所有中断服务程序入口地址（中断向量）的表格，即存放中断服务程序入口地址的表。8086 可处理 256（0~FFH）种中断，每类中断的中断向量为 4 个字节，要占用 $4 \times 256 = 1\text{K}$ 字节，位于内存 00000H~003FFH 的区域中（程序和数据不能占用此区域）。将中断类型号 n 乘以 4 就得到该类型的中断向量的地址，就能找到该中断向量。

**理解**：中断向量表是一块固定的内存区域，按中断类型号顺序存放 256 个中断向量。给定类型号 n，该向量所在地址 $= n \times 4$。表中存放的是入口地址而不是中断服务程序本身。该区域位于绝对地址最低的 1KB（00000H~003FFH），用户程序和数据不能占用；若被破坏，计算机系统无法正常工作。

**作用**：8086 中断系统的核心数据结构。CPU 响应中断时通过它找到服务程序入口地址；后续"设置中断向量"（MOV 直接设置或 DOS 功能调用 25H/35H）等内容都以它的存储格式为前提。

---

### 知识点 11：中断类型号

**定义**：用于管理中断向量表的编号，8086 的 256 类中断各有一个中断类型号 n（0~255）。中断类型号 n 乘以 4（即 n 左移 2 位）就得到该类型中断向量的存放地址。教材标准定义中常用类型号：除法错 n=0、单步 n=1、NMI n=2、断点 n=3、溢出 n=4。

**理解**：中断类型号是中断向量的编号，也是中断向量表的管理索引。存储地址计算公式：向量地址 $= n \times 4$。类型号的来源因中断类型而异：内部中断由指令本身或固定约定给出（如 INTO 固定为 4，NMI 固定为 2），可屏蔽中断由 8259A 在中断响应时提供。

**作用**：连接中断源与中断向量的关键量，是中断向量表寻址计算的依据；例 8.1、例 8.2 的正推与反推计算都基于"n×4"这一关系。

---

### 知识点 12：中断优先级

**定义**：按中断源的重要性和实时性排出的响应中断的次序，称为中断优先级。在 8086 中，中断优先级从高到低的次序为：除法错、INT n、INTO（最高级，同一行的有同等优先级）；NMI（次高级）；INTR（较低级，由 8259A 引入）；单步中断（最低级）。低级中断可以被高级中断打断，进行中断嵌套。

**理解**：多个中断同时请求时，CPU 按固定次序决定先响应哪一个。8086 的次序由内部查询顺序决定：执行完每条指令后，按"内部中断（除法错、INT n、INTO）→ NMI → INTR → 单步"的顺序依次检查。同一行中的中断（除法错、INT n、INTO）有同等优先级，彼此不能互相打断。优先级高低决定了两件事：同时请求时的响应先后；服务过程中能否被其他中断打断。

**作用**：解决多个中断源同时请求时的响应次序问题，是中断嵌套的前提（高级中断可以打断低级中断）。

---

### 知识点 13：中断优先级（8259A 的固定优先级次序）

**定义**：8259A 中断控制器对其 8 个中断请求输入端 IR0~IR7 规定固定优先级：优先级从高到低排列的次序为 IR0、IR1、IR2、IR3、IR4、IR5、IR6、IR7，即 IR0 优先级最高、IR7 优先级最低。当多个中断请求同时出现时，8259A 只允许优先级最高的请求最先得到服务。

**理解**：8259A 的 8 个请求输入端各连接一个中断源，每个输入端的编号同时表示其优先级次序。当 IR2 和 IR4 同时提出请求时，8259A 比较两者的编号，编号小者（IR2）优先级高，先为 IR2 服务，IR4 等待。在嵌套过程中，只有编号更小（优先级更高）的新请求才能打断正在服务的中断；已经服务的请求用 EOI 命令清除其服务寄存器后，8259A 才允许同级或更低级的新请求（如等待中的 IR4）被响应。

**作用**：中断嵌套得以实现的前提。它与知识点 12 所述 8086 各中断源的软件优先级（除法错、INT n、INTO → NMI → INTR → 单步）分属两个层次：前者是 8259A 对 INTR 引脚所带多级中断源的硬件判优，后者是 CPU 对整个中断系统的查询判优。掌握后能够解释"同时请求时先响应谁、服务期间谁能打断谁"。

### 知识点 14：中断嵌套

**定义**：CPU 正在执行中断服务程序时，若有优先级较高的中断源提出请求，则将正在处理的中断暂时挂起，先为高级中断服务，服务完后再返回较低级中断，称为中断嵌套。

**理解**：嵌套的触发条件同时具备两点：当前正在执行某中断服务程序；新提出请求的中断优先级更高。执行次序：暂停当前服务 → 执行高优先级服务 → 高优先级服务结束后返回被暂停处继续执行。

8086 的实现方式：机器进入中断服务程序后，硬件会自动关中断（IF=0），因此默认不允许嵌套；只有用 STI 指令（IF=1）将中断打开后，才允许高级中断进入，实现中断嵌套。中断服务程序结束前，必须用 EOI 命令结束该级中断（EOI 是 8259A 的命令），并用 IRET 指令返回到中断前的断点处继续执行原程序。若在中断服务程序中不安排 STI 指令，则高级中断不能打断低级中断，不能实现嵌套。

课件嵌套示例的完整执行次序：主程序运行中 IR2、IR4 同时请求；IR2 优先级高，先服务 IR2；IR2 服务程序中用 STI 开中断；IR1 提出请求（优先级高于 IR2），IR2 被挂起，转去服务 IR1；IR1 结束前用 EOI 命令清除 IR1 的服务寄存器，结束 IR1 中断，并用 IRET 返回 IR2 服务程序继续运行；IR2 运行至 EOI 命令时结束 IR2 服务，开始响应 IR4 中断；IR4 结束后由 IRET 返回 IR2 服务程序，最后从 IR2 返回主程序。

**作用**：中断系统的重要运行机制，保证更紧急的事件可以先被处理。它是中断优先级机制在 8086 系统中的具体应用形式，后置关联中断处理过程（硬件默认关中断、服务程序需自行开中断）与中断向量设置（嵌套的每级服务程序都经中断向量表转入）。

### 知识点 15：可屏蔽中断的响应和处理流程

**定义**：8086 对可屏蔽中断（INTR 引脚请求）的响应与处理流程为：CPU 检查 INTR 引脚有无中断请求，若无，继续取下一条指令执行；如有（且 IF=1）则响应中断。响应后硬件自动完成关闭中断和保护断点操作，将下一条要执行指令的 CS 和 IP（断点）推入堆栈；然后寻找中断服务程序的入口地址，找到后转入相应的中断服务程序执行；中断服务结束后恢复现场、开中断、返回断点。

**理解**：该流程由四个阶段顺序构成。第一阶段查看中断请求：每条指令执行后 CPU 检查 INTR 引脚电平。第二阶段准备工作：由硬件自动完成，不占程序指令，内容是关中断（IF=0）和把断点 CS:IP 压栈。第三阶段执行中断服务：CPU 依据中断类型号计算中断向量地址，取出服务程序入口，跳转执行服务程序。第四阶段中断返回：恢复现场（各寄存器与标志），开中断，返回断点继续原程序。

**作用**：8.1.2 节的总框架，概括 8086 响应 INTR 请求的完整路径。后文的"中断查询 → 中断响应 → 中断处理和返回"三部分是对这一框架的逐项细化。

---

### 知识点 16：中断查询（查询顺序与优先级）

**定义**：8086 在执行完每条指令后，按固定顺序检查四类中断：内部中断、NMI 非屏蔽中断、INTR 可屏蔽中断、单步中断；只要查到有中断请求，即进入中断响应过程。中断查询的顺序决定了各中断源的优先级。

**理解**：查询在每条指令执行结束后自动进行，逐项检查：先查内部中断，有则响应；没有则查 NMI；没有则查 INTR；没有则查单步中断；都没有则执行下一条指令。因为先查到的先响应，所以查询次序即优先级次序：内部中断最高、NMI 次之、INTR 再次、单步中断最低。内部中断由当前指令本身产生，与当前指令执行直接相关，排在最前；单步中断用于调试，只在其他中断都不存在时才进入，排在最后。

**作用**：中断查询是 8086 中断响应与处理三个部分的第一部分，决定"有无中断、响应哪一个中断"，同时解释了 8086 系统级中断优先级（除法错、INT n、INTO → NMI → INTR → 单步）的来源。

---

### 知识点 17：中断响应（中断类型码与中断向量指针）

**定义**：中断响应阶段根据中断源的中断类型码 n，找到该中断向量的指针，指针地址为 n×4，即在中断向量表中按 $n \times 4$ 计算类型号为 n 的中断向量的存放首地址。

**理解**：每个中断源对应一个 8 位中断类型码 n（取值 0~255）。中断向量表从内存 0000:0000 开始存放，每个中断向量占 4 个字节，其中偏移地址 2 字节在前、段基址 2 字节在后。类型码 n 的向量存放在以 $n \times 4$ 为首地址的连续 4 个单元：偏移地址存于 $n \times 4$ 单元，段基址存于 $n \times 4 + 2$ 单元。响应中断就是用类型码算出该地址、读出服务程序入口，为转入服务程序做准备。

**作用**：中断响应是三个部分的第二部分，完成"从中断请求到中断服务程序入口地址"的转换，是中断向量表机制的核心应用；后置关联中断向量的设置方法（写入的就是这个 $n \times 4$ 单元）。

---

### 知识点 18：中断处理过程（硬件自动完成的工作）

**定义**：中断处理过程开始后，硬件自动执行以下工作：保护 FLAG（保证主程序正确性）；暂存 TF 标志（不允许在中断服务程序中单步运行程序，先暂存到 TEMP 中）；将 IF、TF 标志清零（关中断，默认不嵌套；禁止单步执行）；保护断点，把 CS:IP 入栈。此后把中断向量装入 CS:IP，进入中断服务。

**理解**：这四项操作由硬件在转入服务程序前自动完成，不需要程序指令安排，每项各有目的。保护 FLAG 与保护断点 CS:IP 是为了中断返回时能恢复中断前的完整状态，保证主程序正确性。TF 先暂存到 TEMP 再清零：清零使中断服务程序内部不会按单步方式运行；暂存使返回后可以恢复 TF 原值（若本中断本身是单步中断，则据 TEMP 继续调用单步中断）。IF 清零即关中断，使 CPU 默认不响应新的可屏蔽中断；若需嵌套，服务程序中必须用 STI 重新置 IF=1。

**作用**：中断处理过程是三个部分的第三部分，规定从断点保护到进入用户服务程序之间 CPU 的固定动作序列。用户编写中断服务程序前必须知道这些自动动作，才能正确安排开中断（STI）、保护现场等语句；服务程序本身应短小精干、保护现场。

---

### 知识点 19：IRET 中断返回指令

**定义**：IRET 是中断返回指令，其功能为：把堆栈中保存的断点地址恢复给 CS 和 IP；把堆栈中保存的 FLAGS 内容恢复给标志寄存器 FR；使 CPU 返回到主程序的断点处继续执行。

**理解**：中断发生时硬件按 FLAGS、CS、IP 的顺序压栈保存；IRET 执行时从堆栈中依次弹出这三个值，恢复到对应寄存器。恢复 FLAGS 使主程序的标志状态（包括 IF、TF）还原为中断前的值；恢复 CS:IP 使程序从断点处继续执行。因此 IRET 的弹出顺序与中断响应时硬件的压栈顺序对应，两者配合实现完整的状态恢复。

**作用**：IRET 是每个中断服务程序结束的固定出口，区别于普通子程序返回指令 RET（RET 不恢复 FLAGS）。在中断嵌套中，每级服务程序结束时各执行一次 IRET，实现逐级返回：IR1 结束用 IRET 返回 IR2，IR4 结束用 IRET 返回 IR2，最后从 IR2 用 IRET 返回主程序。

### 知识点 20：中断向量的设置（MOV 直接设置法 + DOS 功能调用法）

**定义**：中断向量的设置是把用户中断服务程序的入口地址写入中断向量表相应单元，常用两种方法。

- 方法一（MOV 直接设置法）：利用 MOV 指令，直接把类型号为 N 的中断服务程序入口地址送到中断向量表的相应单元——将中断服务程序入口地址的偏移地址送到以 $4 \times N$ 为首地址的字单元中，并将其基地址送到以 $4 \times N + 2$ 为首地址的字单元中。
- 方法二（DOS 功能调用法）：通过 INT 21H 的 25H/35H 功能设置与取得中断向量。设置中断向量（25H 号功能）：入口参数 AL=中断类型号 N，DS:DX=中断向量（中断服务程序入口地址），AH=25H（DOS 功能号）；执行 INT 21H 指令后，将 AL 指定的类型号为 N 的中断向量（DS:DX）置入中断向量表。取得中断向量（35H 号功能）：入口参数 AL=中断类型号 N，AH=35H（DOS 功能号）；执行 INT 21H 指令后，N 号中断的中断向量从中断向量表中取到 ES:BX。

**理解**：中断向量表位于内存 0000 段，表内第 N 号向量的偏移地址单元地址是 $4 \times N$、段基址单元地址是 $4 \times N + 2$。方法一设置时先把 ES 置 0 指向向量表段，把 $4 \times N$ 送 BX 作表内偏移，然后 `MOV ES:[BX], AX` 写入入口偏移地址、`MOV ES:[BX+2], AX` 写入入口段基址，每条 MOV 写一个字（2 字节），两次写满 4 字节的向量项；其优点是直接、不依赖 DOS，缺点是直接写绝对内存地址可能破坏系统数据，课件 TIP 注明"这种方法并不安全，一般不建议采用"。方法二完成的工作与方法一相同，但写入向量表的具体操作由 DOS 系统程序完成，程序只需提供类型号（AL）与入口地址（DS:DX），不直接接触绝对内存地址，课件 TIP 注明"相对安全，建议采用"。35H 功能用于读出某类型号当前的中断向量，结果放在 ES:BX。两个功能配合形成标准流程：先用 35H 读出原向量并压栈保存，再用 25H 写入用户新向量；主程序使用该中断结束后，再把保存的原向量用 25H 写回，从而不破坏系统原有中断功能。

**作用**：设置中断向量的两种常用方法，互相并列。方法一是例 8.15 的解题依据；方法二是例 8.16、例 8.17 及例 8.18 主程序的解题依据；"读出—保存—设置—使用—恢复"流程是用户程序接管系统中断时的通用编程模式。

### 知识点 21：中断处理程序的总体框架（主程序 + 服务程序）

**定义**：用户编写的中断处理程序由主程序与中断服务程序两部分构成。主程序依次完成：取出并保存原中断向量（35H 功能）、设置新中断向量（25H 功能）、开放 8259A 对应中断源（IMR 相应位清 0）、用 STI 开中断、执行用户任务（软件延时，期间发生中断）、恢复原中断向量、返回 DOS。中断服务程序依次完成：保护现场寄存器、STI 开中断（允许嵌套）、执行中断任务、向 8259A 发 EOI 命令、恢复现场、IRET 返回。

**理解**：主程序各步骤的顺序由因果决定。先"取原向量"是为了保存，供程序结束时恢复，防止退出后系统定时中断指向已失效的地址；再"设新向量"使中断发生时转向用户服务程序；随后"开放 IR0"是 8259A 级的开放（IMR 的 D0 清 0），使 IR0 请求能送达 CPU；"STI"是 CPU 级的开放（IF=1），两级都开放后中断才能真正被响应。服务程序中先保护现场，防止服务程序修改的寄存器破坏主程序现场；STI 使更高优先级中断可打断本服务程序实现嵌套；EOI 通知 8259A 本中断服务结束，使其允许同级及低级中断再次请求；IRET 恢复断点与标志寄存器。

**作用**：中断处理程序的标准写法，例 8.18 主程序与服务程序均按此框架展开。

---

### 知识点 22：8259A 中断屏蔽寄存器 IMR 的开放操作

**定义**：8259A 的中断屏蔽寄存器 IMR 的端口地址为 21H，其 D0 位对应 IR0 引脚。用 `IN AL,21H` 读入 IMR，用 `AND AL,0FEH` 将 D0 位清 0，再用 `OUT 21H,AL` 写回，即可开放 IR0 中断请求（0FEH = 1111 1110B）。

**理解**：IMR 某位为 1 时，对应 IR 引脚的中断请求被屏蔽；某位为 0 时，对应中断被允许。0FEH 与 AL 相与，只把 D0 清 0、其余 7 位保持不变，因此只开放 IR0（定时中断），不改变其他中断源原有的屏蔽状态。本例中开放 IR0 是因为 8253 的定时中断经 IR0 进入。该操作是 8259A 一级的"开中断"，必须与 CPU 级的 STI（IF=1）配合，两级同时开放后定时中断才能真正进入 CPU。

**作用**：中断处理程序主程序框架中"开放中断源"环节的具体实现。前置知识：8259A 的 IMR 寄存器；与 EOI 同属对 8259A 的软件操作。

### 知识点 23：8259A 的 EOI 结束命令

**定义**：中断服务程序结束前，必须用 EOI 命令结束该级中断：执行 `MOV AL,20H`；`OUT 20H,AL`，向 8259A 命令端口（20H）输出 EOI 命令字（20H），通知 8259A 该级中断服务结束。EOI 是 8259A 的命令。

**理解**：8259A 在响应某级中断后会将该级记录在服务寄存器 ISR 中，并屏蔽同级及更低级中断的请求；若不加处理，该级中断结束后同级中断也无法再次被响应。EOI 命令将 ISR 中当前最高优先级的中断记录清除，解除这一封锁。例 8.18 在主服务路径和 EXIT 出口统一执行 EOI，保证每次中断返回后 8259A 能接受下一次定时中断。

**作用**：中断服务程序结束的标准收尾动作，与 IRET 配合构成完整的中断返回（IRET 返回断点，EOI 通知 8259A）。

### 知识点 24：软件双重循环延时

**定义**：用寄存器作计数器、执行 DEC/JNZ 循环构成的软件延时：外层循环初值 DI=20000，内层循环初值 SI=30000；内层循环每执行一遍 SI 从 30000 减到 0，外层循环每执行一遍 DI 减 1，共执行约 $20000 \times 30000$ 次 DEC/JNZ，累计延时一定时间（大于 10 秒）。

**理解**：每条指令的执行时间由 CPU 时钟决定、基本固定；重复执行足够多次指令即可累计出所需的延时时间。两层循环形成"乘法"结构：外层执行 20000 次，每执行一次外层都要完整执行一遍内层（30000 次），因此总循环次数约为两者的乘积。延时期间中断照常发生——CPU 在两次循环迭代之间响应中断，进入服务程序执行后再返回断点继续循环，所以延时过程同时也是"等待中断发生"的过程。

**作用**：无需额外硬件的粗略延时手段，用于保证主程序运行时间足够长（大于 10 秒），期间至少发生一次（实际为多次）定时中断。与 8253 硬件定时互为补充：硬件定时精度高，软件延时实现简单。

### 知识点 25：PC 机定时中断（8253 计数器 0 与 1CH 中断）

**定义**：IBM PC 中，8253 定时器计数器 0 被初始化为方式 3（方波发生器）、二进制计数；计数初值 $n=0$（$0$ 表示按 $2^{16}=65536$ 计数）。OUT0 输出的方波频率为 $f = 1.19318\,\mathrm{MHz}/65536 \approx 18.2\,\mathrm{Hz}$，周期为 $T = 1/f \approx 55\,\mathrm{ms}$。OUT0 经 8259A 的 IR0 引脚引入 CPU，所对应的中断类型号为 1CH。系统原有的 1CH 中断服务程序不做任何具体工作，只有一条 IRET 指令。

**理解**：计数器 0 从初值 65536 开始，按 1.19318 MHz 的时钟频率递减计数，每计 65536 个脉冲耗时 $65536/1193180 \approx 0.0549\,\mathrm{s}$，即约 55 ms。计满一个周期时 OUT0 输出一个方波半周期（方式 3 下输出连续方波），同时经 IR0 向 CPU 发出一次中断请求，因此 CPU 每隔约 55 ms 进入一次类型号为 1CH 的中断服务程序。系统原有的 1CH 服务程序只有一条 IRET，即系统默认进入后立即返回、不做处理，这一空入口正是用户接管该中断、实现自定义定时任务的基础。

**作用**：为例 8.18 提供固定的时间节拍（55 ms/次）。前置知识：8253 方式 3 与计数初值计算；后置知识：利用该节拍累计实现 10 秒定时的 COUNT 计数方案。

### 知识点 26：PC 机扬声器控制（8253 计数器 2 + 8255A PB0/PB1）

**定义**：PC 机扬声器由 8253 计数器 2 与 8255A 共同控制。计数器 2 工作于方式 3，计数初值 $n=533\mathrm{H}=1331$，OUT2 输出的方波频率为 $1.19318\,\mathrm{MHz}/1331 \approx 896\,\mathrm{Hz}$。GATE2 受 8255A-5 的 PB0 控制：PB0=1 时允许计数，使 OUT2 输出方波。扬声器还受 8255A 的 PB1 控制：PB1=1 时扬声器才能发声。8255A 的 PB 端口地址为 61H，其中 D0 位对应 PB0，D1 位对应 PB1。

**理解**：发声需要同时满足两个条件。第一，PB0=1 使 GATE2 为高，计数器 2 被允许计数，OUT2 才能输出 896 Hz 方波；第二，PB1=1 使扬声器电路接通。两个条件分别控制"方波是否产生"和"方波是否送到扬声器"，任一条件不满足都不发声。在 61H 端口上，D0 位控制 PB0，D1 位控制 PB1，因此对 61H 端口的 D1 位反复取反即可控制扬声器的通与断。

**作用**：为"响铃"提供硬件手段，是例 8.18 任务 3 的硬件基础。前置知识：8253 方式 3、8255A B 口位控制；与计数器 0 同为 8253 的不同通道，属于并列知识点。

### 知识点 27：10 秒定时的 COUNT 计数方案

**定义**：利用每 55 ms 一次的 1CH 定时中断实现 10 秒定时：中断服务程序每执行一次将计数变量 COUNT 减 1；中断 182 次后，$55\,\mathrm{ms} \times 182 = 10010\,\mathrm{ms} \approx 10\,\mathrm{s}$，10 秒时间到；此时 COUNT 减为 0，服务程序执行响铃一次并显示信息，随后将 COUNT 重新赋值为 182，开始下一次 10 秒定时。

**理解**：55 ms 是由硬件（计数器 0）提供的固定时间单位，无法直接产生 10 秒整的时间，因此采用"累计"方法：把 10 秒拆成 182 个 55 ms 的单位（$10000/55 \approx 181.8$，取 182，误差仅 10 ms）。COUNT 的递减过程就是计时过程——每次中断减 1，减到 0 即累计满 182 次。COUNT 首次值置为 1：第一次进入服务程序时 DEC COUNT 即得 0，立即完成一次响铃与显示（随后重置为 182），此后按每 182 次中断（约 10 秒）响铃一次的规律运行。

**作用**：定时中断实现软件定时的核心方案，是例 8.18 的中枢逻辑，连接定时中断与响铃显示任务。

### 知识点 28：8255A PB 口（61H）发声控制程序段

**定义**：控制扬声器发声的程序段为：`MOV DX,100` 设定扬声器通断 100 次；`IN AL,61H` 读入 8255A PB 端口；`AND AL,0FCH` 使 PB1PB0=00；循环体 SOUND 中执行 `XOR AL,02H`（对 61H 口的 D1 位即 PB1 取反）、`OUT 61H,AL`（输出，PB1 由 1→0、由 0→1 交替）、`MOV CX,140H` 并执行 `LOOP WAIT1` 延时（使方波有一定宽度）；每循环一次 `DEC DX`，`JNE SOUND` 判断 100 次通断是否完成。

**理解**：0FCH = 1111 1100B，与操作将 D1、D0 同时清 0（PB1=0、PB0=0）。02H = 0000 0010B，XOR 操作每次只翻转 D1 位：D1 由 0 变 1 使扬声器接通，由 1 变 0 使扬声器断开，如此交替 100 次形成通断方波。每次输出后执行 CX=140H 的 LOOP 循环（约 320 次迭代）产生一段延时，控制方波高、低电平各保持一定宽度，从而得到可闻的"嘀"声。DX 寄存器承担通断次数计数（初值 100），与 LOOP 前的 CX 赋值互不影响（CX 与 DX 是不同寄存器）。

**作用**：响铃任务（任务 3）的程序实现。前置知识：扬声器控制的硬件关系、8255A 端口操作。

### 知识点 29：响铃次数控制（count0 变量 + WAIT0 等待循环）

**定义**：要求响铃 10 次后结束程序时，在数据段增设计数变量 count0（DB 10，初始化值为 10）；中断服务程序中每次响铃（10 秒时间到）执行一次 `dec count0`；主程序在软件延时结束后增加 `WAIT0: cmp count0,0 / JNZ WAIT0` 循环，等待最后一次响铃完成（count0=0）后再恢复原中断向量并返回 DOS。

**理解**：主程序软件延时结束的时刻与第 10 次响铃完成的时刻不一定重合——延时结束时可能只响了几次铃，若立即恢复原中断向量，后续响铃将不再发生。因此用 count0 记录已响铃次数：服务程序每响铃一次将其减 1；主程序延时结束后进入 WAIT0 循环反复比较 count0 与 0，只要 count0≠0 就继续等待，直到第 10 次响铃完成（count0=0）才退出循环、恢复原向量、结束程序。等待循环期间中断照常发生，服务程序得以继续执行响铃并递减 count0。

**作用**：对原例的扩展改进——把"运行一定时间后停止"改为"响铃固定次数后停止"，属于 COUNT 计数思想在主程序侧的延伸应用。

### 知识点 30：中断系统的几点总结

**定义**：中断系统具有以下基本性质：①中断请求是随机发生的；②中断服务是可以嵌套的；③中断系统需要软件和硬件的支持。

**理解**：①随机性——中断请求产生的时刻由外部事件（定时器计满、键盘输入等）决定，CPU 无法预知，因此中断采用"请求—响应"机制，CPU 在执行每条指令后检查有无中断请求，而不是定时查询。②可嵌套——正在执行低优先级中断服务程序时，更高优先级的中断可以打断它，待高优先级服务完成后再返回继续执行低优先级服务（用 STI 开中断 + EOI/IRET 实现）。③软硬件结合——硬件负责请求的产生与响应（INTR/NMI 引脚、8259A 的判别与屏蔽、响应时自动保护断点与标志），软件负责中断向量表的设置、中断服务程序的编写、EOI 命令的发出。

**作用**：本章的总结性结论，是对前述全部知识点的归纳，属顶层结论性知识点。

### 2. 8259A 的八级中断源（第 4 页）

8259A 的输入引脚 IR0~IR7 可引入 8 级中断：时钟、键盘、串行通信口 COM1 和 COM2、硬盘、软盘、打印机。经芯片内部判别后，将优先级高的中断请求信号送到 INT 引脚，它连接 CPU 的 INTR 引起中断请求。

### 3. 中断响应和返回（第 9 页）

CPU 响应中断时，首先把 CS、IP 寄存器的值（断点）以及标志寄存器 FLAGS 的值推入堆栈保护；然后找到中断服务程序的入口地址，转去执行相应的中断服务程序；中断服务程序结束时，执行中断返回指令 IRET 返回断点，程序继续执行。核心问题：8086 系统如何寻找中断服务程序的入口地址——答案是借助中断向量表按类型号 n×4 寻址。

### 4. 中断向量表要点（第 11–13 页）

- 与 CALL 子程序相比，中断调用是段间调用（不是段内调用），故入口地址必须包括段地址和有效地址。
- 1 个中断向量包括 4 个字节：偏移地址放在低地址，段地址放在高地址。
- 管理方式：用中断类型号（中断号）管理中断向量表。
- 8086 可处理 256（0~FFH）种中断；向量区总大小 $4 \times 256 = 1\text{K}$ 字节，位于 00000H~003FFH；程序和数据不能占用此区域。
- 存放规则：IP 在低地址，CS 在高地址。
- 页内示例（n=2 的 NMI 中断）：$2 \times 4 = 8 = 00008\text{H}$，其中断服务程序入口地址存放在 00008H 开始的 4 个字节内；IP 存在 00008H 开始的字单元，CS 存在 0000AH 开始的字单元。

### 5. 中断向量表的保护与思考题（第 16 页）

- TIP：中断向量表对计算机系统非常重要，如果中断向量表被破坏，则计算机系统无法正常工作。如何正确写入和保护中断向量表——留待后面讲述。
- 思考题：1）比较子程序的入口地址保存位置和中断向量表；2）比较调用子程序过程和调用中断服务程序过程。

### 6. 中断优先级与嵌套的引子（第 17 页）

- 优先级的问题：计算机系统有多种中断；中断又可能是随机产生的；如果同时有多个中断源提出请求怎么办？这就是中断优先级判别的问题。
- 嵌套的问题：正在响应一个中断（执行中断服务程序中）时，有另外一个更高优先级的中断提出请求怎么办？可以执行完高优先级的中断后，再完成当前中断——这就叫中断嵌套。

### 7. 8086 中断优先级次序表（第 18 页）

| 优先级 | 中断类型 | 说明 |
|---|---|---|
| 最高级 | 除法错、INT n、INTO | 同一行的有同等优先级 |
| 次高级 | NMI | |
| 较低级 | INTR | 由 8259A 引入 |
| 最低级 | 单步中断 | |

低级中断可以被高级中断打断，进行中断嵌套。

### 8. 8086 实现中断嵌套的软硬件配合（第 20 页）

1. 机器进入中断服务程序后，硬件会自动关中断（IF=0）。
2. 只有用 STI 指令（IF=1）将中断打开后，才允许高级中断进入，实现中断嵌套。
3. 中断服务程序结束前，必须用 EOI 命令结束该级中断（EOI 是 8259A 的命令）。
4. 用 IRET 指令返回到中断前的断点处继续执行原程序。

### 9. 中断嵌套执行过程的逐页叙述（第 21–24 页）

- 第 22 页：主程序运行中，IR2、IR4 同时提出中断请求。IR2 优先级高，先为 IR2 服务。在 IR2 的服务程序中，要用 STI 指令开中断，允许更高级中断进入。8259A 的优先级从高到低排列的次序为 IR0~IR7。
- 第 23 页：IR2 服务时，IR1 提出请求，IR2 被挂起，为 IR1 服务。IR1 结束前用 EOI 指令清除 IR1 的服务寄存器，结束 IR1 中断，并用 IRET 指令返回 IR2 服务程序，继续运行。运行至 EOI 命令时结束 IR2 的服务，可以开始响应 IR4 中断。
- 第 24 页：IR4 结束后，由 IRET 指令返回 IR2 服务程序，最后从 IR2 返回主程序。在中断服务程序中，如不安排开中断指令 STI，则高级中断不能打断低级中断，也就不能实现中断的嵌套。

### 10. 中断嵌套涉及的三条关键指令/命令

| 指令/命令 | 作用 | 位置 |
|---|---|---|
| STI | 置 IF=1，开中断；硬件进入中断时已自动关中断（IF=0），服务程序中用 STI 后才允许更高级中断进入，实现嵌套 | 中断服务程序内 |
| EOI | 8259A 的命令，结束该级中断，清除该级中断的服务寄存器 | 该级中断服务结束前 |
| IRET | 恢复断点 CS:IP 与 FLAGS，返回到被中断的程序继续执行 | 中断服务程序出口 |

### 11. 8086 中断响应与处理的三个部分（第 27 页）

1. **中断查询**：查看是否有中断。
2. **中断响应**：形成中断类型号。
3. **中断处理和返回**：保护断点，保护 Flags，执行中断服务程序，恢复 Flags，恢复断点。

### 12. 中断查询顺序（第 28 页）

执行完每条指令后，CPU 顺序检查：内部中断 → NMI 中断 → INTR 中断 → 单步中断；如有中断，则进入中断响应过程；中断查询的顺序也决定了它们的优先级。对应第 18 页的优先级次序：除法错、INT n、INTO（最高级，同一行的有同等优先级）→ NMI（次高级）→ INTR（较低级，由 8259A 引入）→ 单步中断（最低级）。

### 13. 中断处理过程的附加细节（第 30–31 页）

- 硬件自动完成的工作：保护 FLAG（保证主程序正确性）；暂存 TF 标志（不允许在中断服务程序中单步运行程序，先暂存到 TEMP 中）；IF、TF 标志清零（关中断，默认不嵌套；禁止单步执行）；保护断点（把 CS:IP 入栈）。
- 进入中断服务后：把中断向量给 CS:IP。
- NMI 细节：如果又有 NMI 进入，NMI 中断处理后，会清除 CPU 中锁存的 NMI 请求信号，使加在 CPU 上的 NMI 只会被 CPU 识别一次。
- 单步细节：判断 TEMP 保存的 TF 标志，如果本中断是单步中断，则继续调用单步中断。
- 中断服务程序编写要求：短小精干，保护现场。示例任务：采集数据。

### 14. IRET 的功能（第 32 页）

1. 堆栈保存的断点地址给 CS 和 IP。
2. 堆栈保存的 FLAGS 内容恢复给 FR。
3. 返回到主程序断点执行。

### 15. INTA 中断响应信号（第 33 页流程图）

第 33 页为完整的 8086 中断响应与处理流程图：覆盖中断查询（顺序检查内部中断、NMI、INTR、单步中断）、中断响应（形成中断类型号）、中断处理（保护 FLAG、暂存 TF、IF/TF 清零、保护断点、取中断向量、执行服务程序）与返回（IRET）全流程；图中出现 INTA，即中断响应信号——CPU 响应可屏蔽中断时通过 INTA 引脚向 8259A 发出应答脉冲，8259A 收到后经数据总线送出中断类型码。

### 16. 中断向量的设置背景：256 类中断的分配（第 34 页）

PC 机对 256 类中断，有些已分配了固定功能，规定了中断服务程序的入口地址：

- 类型号 $n=0\sim4$：专用中断（0 除法错、1 单步、2 NMI、3 断点、4 溢出）。
- 类型号 $n=5$：打印屏幕中断。
- 类型号 $n=08\mathrm{H}\sim0\mathrm{FH}$：分配给 8259A。
- 类型号 $n=08\mathrm{H}\sim0\mathrm{FH}$ 和 $n=70\mathrm{H}\sim\mathrm{FFH}$：分配给 PC/AT 机。

### 20. 预备知识中的数值与事实（第 42–43 页）

- PC 机定时中断（计数器 0）：
  - 初始化方式：方式 3，二进制计数；初值 $n=0$，即按 $2^{16}=65536$ 计数；
  - 输出频率：$f = 1.19318\,\mathrm{MHz}/65536 \approx 18.2\,\mathrm{Hz}$；
  - 周期：$T = 1/f \approx 55\,\mathrm{ms}$；
  - OUT0 对应的中断号为 1CH；
  - 原中断服务程序不做任何事，只有一条 IRET 指令。
- 扬声器控制（计数器 2）：
  - 方式 3，计数初值 $n=533\mathrm{H}=1331$；
  - OUT2 方波频率：$1.19318\,\mathrm{MHz}/1331 \approx 896\,\mathrm{Hz}$；
  - GATE2 受 8255A-5 的 PB0 控制：PB0=1 时允许计数，OUT2 输出方波；
  - 扬声器受 8255A 的 PB1 控制：PB1=1 才能响。
- 10 秒定时计算（第 44 页）：
  - 中断服务程序每中断一次 COUNT 减 1；中断 182 次后时间到；
  - 验证：$55\,\mathrm{ms/次} \times 182\,\mathrm{次} = 10010\,\mathrm{ms} \approx 10\,\mathrm{s}$；
  - COUNT 减为 0 时：响铃一次、显示 "The bell is ring."、COUNT 重新赋值为 182，开始下一次 10 秒定时。
- 主程序功能（第 44 页）：对中断进行初始化设置；执行软件延时程序（期间发生中断）；延时完成后恢复原来中断；退出整个程序。

### 25. 本书件涉及的中断机制事实（贯穿全件）

- 中断类型号 1CH 对应的向量存放于中断向量表 0000:4×1CH = 0000:0070H 开始的 4 个字节；25H 功能正是把 RING 的入口地址（段基址→4N+2 字单元，偏移量→4N 字单元）写入该处；
- 35H 功能把 1CH 号中断的现向量从向量表读到 ES:BX，随后 PUSH ES、PUSH BX 入栈保存；恢复时按先进后出次序 POP DX（对应 BX，偏移量）、POP DS（对应 ES，段基址），重组为 DS:DX 后交 25H 功能写回；
- 中断响应时硬件自动关中断（IF=0），因此服务程序中必须用 STI 才允许嵌套；服务结束用 EOI（对 8259A）与 IRET（对 CPU）两道命令收尾。

## 解题方法汇总

### 方法 1：中断向量地址计算（n×4 指针法）

- **适用场景**：给定中断类型号求其中断向量在中断向量表中的存放地址（正推）；或已知向量表内地址反推类型号与入口地址（反推）。
- **已知条件**：中断类型号 n（0~255）或向量存放首地址；中断向量表首地址 0000:0000；每个向量占 4 字节（低字为 IP 偏移地址，高字为 CS 段基址）。
- **计算步骤**：
  1. 计算存放首地址：$n \times 4$，即 n 左移 2 位（十六进制下左移 2 位相当于乘 4）。如 $n=31\mathrm{H}$：$31\mathrm{H} \times 4 = 0\mathrm{C}4\mathrm{H}$，首地址为 0000:00C4H。
  2. 分量定位：偏移地址（IP）存放在 $[n \times 4]$ 字单元，段基址（CS）存放在 $[n \times 4 + 2]$ 字单元。如 $n=31\mathrm{H}$：偏移地址在 0000:00C4H，段基址在 0000:00C6H。
  3. 反推时：取向量首地址除以 4（右移 2 位）得类型号 n；读低地址字单元得 IP，读高地址字单元得 CS，合成 CS:IP。
  4. 验证：把求得的 n 代回 $n \times 4$，应与存放首地址一致。
  5. 结果：类型号 n 的向量 = 内存 $n \times 4$ 起的 4 字节（低字为 IP 偏移，高字为 CS 段基址）。
- **常见错误**：忘记乘 4，直接把类型号当存放地址；IP 与 CS 位置写反（IP 应在低地址、CS 在高地址）；类型号是十六进制时按十进制乘以 4（如把 31H 算成 31×4=124D 而不是 0C4H=196D）；用高地址字单元地址（如 0042H）去除以 4，得错类型号；误以为每个中断向量占 2 字节，段基址单元算成 $n \times 4 + 1$。

### 方法 2：用堆栈中转设置/清除 TF 标志

- **适用场景**：需要置 TF=1 以启动单步中断，或清 TF=0 以禁止单步中断；8086 没有直接修改 TF 的指令。
- **已知条件**：FLAGS 寄存器当前内容；目标是对 TF（D8 位）置 1 或清 0。
- **计算步骤**：
  1. PUSHF：把 FLAGS 寄存器内容压入堆栈。
  2. POP AX：把 FLAGS 内容取到 AX。
  3. 置 1：`OR AX, 0100H`（0100H 的 D8=1，使 TF 置 1，其余位不变）；清 0：`AND AX, 0FEFFH`（FEFFH 为 0100H 的反码，使 D8=0，其余位不变）。
  4. PUSH AX：修改后的内容压入堆栈。
  5. POPF：堆栈内容送回 FLAGS 寄存器。
- **常见错误**：试图用不存在的"直接改 TF"指令（如 OR FLAGS, 0100H）；漏掉 PUSHF/POPF 中的某一步导致堆栈不平衡；掩码写错（置 1 掩码应为 0100H 对应 D8 位，清 0 掩码应为 FEFFH）。

### 方法 3：用 MOV 指令直接设置中断向量

- **适用场景**：需要把用户中断服务程序的入口地址写入中断向量表；不借助 DOS 功能调用、直接操作内存的场合（用于了解向量表底层结构；因不安全，实际编程一般不建议采用）。
- **已知条件**：中断类型号 N；中断服务程序入口地址标号 INTR_AD（其 OFFSET 与 SEG 两个分量）；中断向量表所在段地址 0000H。
- **计算步骤**：
  1. 计算向量在表内的偏移量：类型号 N 乘以 4，得 $4 \times N$；段基址单元比偏移单元地址大 2，即 $4 \times N + 2$。这是整个方法的地址依据。
  2. 把 ES 段寄存器置为 0（指向向量表段）：执行 `MOV AX, 0`、`MOV ES, AX`。
  3. 把 BX 置为表内偏移量：执行 `MOV BX, N*4`（汇编程序将 N*4 算成 $4 \times N$ 后作为立即数）。
  4. 取入口的偏移地址：执行 `MOV AX, OFFSET INTR_AD`。
  5. 把偏移地址写入 $4 \times N$ 单元：执行 `MOV ES:[BX], AX`。
  6. 取入口的段基址：执行 `MOV AX, SEG INTR_AD`。
  7. 把段基址写入 $4 \times N + 2$ 单元：执行 `MOV ES:[BX+2], AX`。
  8. 结果：中断向量表中类型号 N 对应的 4 字节（$4 \times N$ 起）装入 INTR_AD 的偏移地址与段基址，即完成 CS:IP 的置入。
- **常见错误**：BX 忘记乘以 4（写成 `MOV BX, N`），导致写入地址错误；偏移地址与段基址写反：把 SEG INTR_AD 写入 ES:[BX]、把 OFFSET INTR_AD 写入 ES:[BX+2]；忘记先把 ES 置为 0（0000H），写入到错误的内存段；直接写绝对内存地址覆盖系统已有中断向量，破坏系统功能（该法本身不安全）。

### 方法 4：用 DOS 功能调用设置与取得中断向量（INT 21H 的 25H/35H）

- **适用场景**：用户程序需要接管（修改）某个中断向量（如 1CH 定时中断），并希望在程序结束前恢复原向量；需要安全、规范地读写中断向量表的场合（课件建议采用）。
- **已知条件**：中断类型号 N；用户新中断服务程序入口地址（SEG 与 OFFSET 两个分量）。
- **计算步骤**（取得并保存原向量）：
  1. 把类型号送 AL：`MOV AL, N`。
  2. 功能号 35H 送 AH：`MOV AH, 35H`。
  3. 执行 `INT 21H`：结果 N 号中断原向量取到 ES:BX（ES=原向量段基址，BX=原向量偏移量）。
  4. 原向量压栈保存：`PUSH ES`、`PUSH BX`（先压段基址，后压偏移量）。
- **计算步骤**（设置新向量）：
  1. 保存 DS 原值：`PUSH DS`。
  2. 取新向量的段基址送 DS：`MOV AX, SEG INTR_AD`、`MOV DS, AX`。
  3. 取新向量的偏移量送 DX：`MOV DX, OFFSET INTR_AD`。
  4. 类型号送 AL、功能号 25H 送 AH：`MOV AL, N`、`MOV AH, 25H`。
  5. 执行 `INT 21H`：结果将 DS:DX 指向的新向量写入类型号 N 对应的表项。
  6. 恢复 DS：`POP DS`（对应第 3 步之前的 `PUSH DS`）；之后运行用户主程序（使用到该中断）。
- **计算步骤**（恢复原向量）：
  1. 弹出原向量：`POP DX`（得到原 BX 值，即原向量偏移量）、`POP DS`（得到原 ES 值，即原向量段基址）。
  2. 再次用 25H 功能写回：`MOV AL, N`、`MOV AH, 25H`、`INT 21H`。
  3. `RET` 结束主程序。
- **结果**：中断向量表 0000:4N 起的 4 个字节被正确改写或复原。
- **常见错误**：25H 功能入口参数放错寄存器：段基址必须在 DS、偏移量必须在 DX，二者颠倒则写入错误向量；35H 功能结果寄存器记错：结果在 ES:BX，不是 DS:DX；弹出原向量时寄存器名变化易混：压栈为 PUSH ES、PUSH BX，弹栈为 POP DX（对应原 BX）、POP DS（对应原 ES），随后 DS:DX 恰好满足 25H 的入口格式；忘记先保存原向量或忘记在程序结束前恢复原中断向量，导致系统原有中断功能丢失。

### 方法 5：中断服务程序编写框架（保护现场→STI→处理→EOI→恢复现场→IRET）

- **适用场景**：编写任何 8086 用户中断服务程序；需要在服务期间响应更高级中断（实现中断嵌套）时。
- **已知条件**：中断类型号与入口地址（经向量表设置）；服务程序要完成的具体任务；服务程序将使用的寄存器；8259A 命令口 20H、EOI 命令字 20H。
- **计算步骤**：
  1. 进入服务程序后，硬件已自动关中断（IF=0）。保护现场：把服务程序用到的寄存器依次入栈——`PUSH DS`、`PUSH AX`、`PUSH CX`、`PUSH DX`。
  2. 设置自身数据段：`MOV AX,DATA`；`MOV DS,AX`。
  3. `STI` 开中断，允许中断嵌套（响应时硬件已自动关中断；若不允许嵌套则不写 STI）。
  4. 执行中断任务：服务程序主体保持短小精干（例 8.18 中为 `DEC COUNT`；`JNZ EXIT`；为 0 时显示信息、响铃、`MOV COUNT,182`）。
  5. 发 EOI：`MOV AL,20H`；`OUT 20H,AL`——该级服务结束前，向 8259A 执行 EOI 命令，清除该级中断的服务寄存器，结束该级中断。
  6. 恢复现场：按压栈的逆序弹出——`POP DX`、`POP CX`、`POP AX`、`POP DS`。
  7. `IRET` 返回主程序断点：恢复 FLAGS 与断点 CS:IP，回到被中断的程序继续执行。
- **常见错误**：服务程序中漏写 STI：高级中断不能打断低级中断，无法实现嵌套；漏写 EOI 命令：8259A 的服务寄存器未被清除，其后同级或更低级中断不再被响应；用 RET 代替 IRET：FLAGS 不恢复，主程序标志状态被破坏；漏保护某寄存器或恢复顺序颠倒（必须后进先出）。

### 方法 6：8259A 中断屏蔽位操作（IMR 开放/屏蔽某级中断）

- **适用场景**：开中断前，允许或禁止 8259A 某一 IR 引脚（如 IR0 定时中断）的中断请求。
- **已知条件**：IMR 端口地址 21H；目标 IR 引脚的位号 i（IR0 对应 D0）。
- **计算步骤**：
  1. `IN AL,21H` 读入当前 IMR。
  2. 按位清零：`AND AL,0FEH`——代入本例：0FEH=1111 1110B，仅 D0=0，开放 IR0，其余位保持不变。
  3. `OUT 21H,AL` 写回。
  4. 结果：IR0 中断请求可从 8259A 送达 CPU（还需 STI 开 IF）。
- **常见错误**：误认为 IMR 位=1 是开放（实际 1=屏蔽）；开放某位时把 AND/OR 方向弄反；掩码写错（如把 0FEH 写成 0EFH）误改其他中断源的屏蔽状态。

### 方法 7：软件双重循环延时

- **适用场景**：对时间精度要求不高、量级较大的粗略延时（如 >10 s），或不便使用定时器硬件的场合。
- **已知条件**：外层初值（本例 DI=20000）、内层初值（本例 SI=30000）。
- **计算步骤**：
  1. `MOV DI,20000` 设外层计数。
  2. 外层循环体：`MOV SI,30000` 设内层计数。
  3. 内层循环：`DEC SI`；`JNZ DELY1`——SI 从 30000 减到 0，共 30000 次迭代。
  4. 外层循环：`DEC DI`；`JNZ DELY`——DI 从 20000 减到 0，共 20000 次迭代；总迭代约 $20000 \times 30000 = 6\times 10^8$ 次 DEC/JNZ。
  5. 结果：总延时大于 10 s（确切时间取决于 CPU 时钟与指令周期）。
- **常见错误**：内外层寄存器层次混淆（SI/DI 与内/外对应关系写反）；延时期间未开中断，中断无法及时响应；把延时时间当作精确值使用。

### 方法 8：定时中断计数法实现 N 秒定时（COUNT 计数方案）

- **适用场景**：利用系统 18.2 Hz（周期 55 ms）定时中断，实现以 55 ms 为单位的定时任务。
- **已知条件**：定时中断周期 $T_0 = 55\,\mathrm{ms}$；目标时间 $T$（本例 10 s）。
- **计算步骤**：
  1. 计算所需中断次数：$n = T/T_0$，代入 $T=10\,\mathrm{s}$、$T_0=55\,\mathrm{ms}$ 得 $n \approx 181.8$，向上取整为 182 次（$55\,\mathrm{ms} \times 182 = 10010\,\mathrm{ms} \approx 10\,\mathrm{s}$）。
  2. 定义计数变量 `COUNT DW 182`（首次值置 1 则第一次进入服务程序即执行任务，随后重置为 182）。
  3. 服务程序每次中断执行 `DEC COUNT`，随后 `JNZ EXIT`——COUNT≠0 表示时间未到，直接转出口。
  4. COUNT=0 时执行定时任务（响铃、显示信息），随后 `MOV COUNT,182` 重置，开始下一周期。
  5. 结果：每约 10 s 执行一次任务，误差为 $10010 - 10000 = 10\,\mathrm{ms}$。
- **常见错误**：COUNT 减到 0 执行任务后忘记重置 182，导致之后每 55 ms 就执行一次任务；中断次数计算错误（如误用 181 次，$55 \times 181 = 9955\,\mathrm{ms}$ 不足 10 s）；未区分 COUNT 的首次值（置 1）与周期值（182）的不同作用。

### 方法 9：8255A PB 口（61H）控制扬声器发声

- **适用场景**：控制 PC 扬声器响铃/发声。
- **已知条件**：61H 为 8255A PB 口地址；D0=PB0（GATE2 使能）、D1=PB1（扬声器开关）；发声需 PB1 在 0/1 间交替并保持一定宽度。
- **计算步骤**：
  1. `MOV DX,100`——设通断次数计数器初值 100。
  2. `IN AL,61H` 读入 PB 口当前状态。
  3. `AND AL,0FCH`——代入 0FCH=1111 1100B，使 PB1PB0=00。
  4. 循环体 SOUND：`XOR AL,02H`（代入 02H=0000 0010B，翻转 D1 位，PB1 由 0→1 或由 1→0）；`OUT 61H,AL` 输出；`MOV CX,140H` 设内层延时计数 320；`LOOP WAIT1` 循环延时形成方波宽度。
  5. `DEC DX`；`JNE SOUND`——判断通断是否满 100 次，未满继续。
  6. 结果：扬声器按软件延时决定的频率通断 100 次，发出"嘀"声。
- **常见错误**：把 0FCH 误写成 0FEH（动了 PB0 位，改变了 GATE2 状态）；忘记 LOOP 延时导致通断频率过高听不到声音；XOR 操作对象写错（如用 02H 以外的值，一次翻转多位）。

### 方法 10：计数变量控制任务执行次数（响铃 10 次后结束程序）

- **适用场景**：要求中断任务（或周期性任务）执行固定次数后程序结束。
- **已知条件**：目标次数（本例 10 次）。
- **计算步骤**：
  1. 数据段定义 `count0 DB 10`，初始化为 10。
  2. 服务程序中在 10 秒时间到、执行显示信息处插入 `dec count0`——每响铃一次 count0 减 1。
  3. 主程序软件延时结束后插入等待循环 `WAIT0: cmp count0,0`；`JNZ WAIT0`——count0≠0 说明 10 次响铃未全部完成，继续等待（等待期间中断照常执行并递减 count0）。
  4. count0=0 时退出等待，恢复原中断向量（方法 4 的恢复步骤），返回 DOS。
  5. 结果：第 10 次响铃完成后程序才结束。
- **常见错误**：主程序不加等待，延时结束立即恢复向量，导致最后几次响铃不再发生；dec count0 插入位置错误（如放在响铃之前，计数与响铃次数错位）；count0 未初始化或定义为字类型与 cmp 用法不匹配。

### 例题 1（页内示例）：中断号 n=2 的 NMI 中断向量的存放

**题干**：
中断号 n=2 的 NMI 中断，其中断服务程序入口地址应存放在哪里？

**解**：

第 1 步：计算中断向量存放首地址：$2 \times 4 = 8 = 00008\text{H}$。
第 2 步：确定存放范围：其中断服务程序入口地址应该存放在 00008H 开始的 4 个字节内，即该中断向量放在 00008H~0000BH 单元。
第 3 步：确定分量位置：IP（偏移地址）存在 00008H 开始的字单元；CS（段地址）存在 0000AH 开始的字单元。
第 4 步：验证：n=2 时 $n \times 4 = 2 \times 4 = 8 = 00008\text{H}$，与存放首地址一致；低地址字放 IP、高地址字放 CS，符合存放规则。

**答案**：NMI 中断向量存放在 00008H~0000BH 单元；IP 在 00008H 字单元，CS 在 0000AH 字单元。

### 例题 2（例 8.1）：中断向量在中断向量表中的存放

**题干**：
【例 8.1】类型号 n=44H 的中断服务程序的入口地址为 3600:2000H，它们在中断向量表中应如何存放？

**解**：

第 1 步：计算向量存放首地址：$44\text{H} \times 4 = 110\text{H}$（44H 左移 2 位）。
第 2 步：确定存放起点：从 110H 单元开始存放该中断向量（共 4 个字节，110H~113H）。
第 3 步：写低地址字（IP 部分）：偏移地址 2000H 存入 110H 字单元，即 $(0110\text{H}) = 2000\text{H}$；按字节存放为 $(0110\text{H}) = 00\text{H}$、$(0111\text{H}) = 20\text{H}$。
第 4 步：写高地址字（CS 部分）：段地址 3600H 存入 112H 字单元，即 $(0112\text{H}) = 3600\text{H}$；按字节存放为 $(0112\text{H}) = 00\text{H}$、$(0113\text{H}) = 36\text{H}$。
第 5 步：用原始数据验证：响应时 CPU 先读 110H 字单元得 IP=2000H，再读 112H 字单元得 CS=3600H，合成入口地址 3600:2000H，与题干给出的入口地址一致；$44\text{H} \times 4 = 110\text{H}$ 与存放首地址相符。

**答案**：该中断向量从 110H 单元开始存放，$(0110\text{H}) = 2000\text{H}$（IP），$(0112\text{H}) = 3600\text{H}$（CS）。

**题干**：
【例 8.2】若在中断向量表中保存某中断向量：(0040H)=240BH，而 (0042H)=D169H，试问该中断的中断类型号 n=？该中断服务程序的起始地址是什么？

**答案**：中断类型号 n=10H；该中断服务程序的入口地址（起始地址）为 D169:240BH。

### 例题 4（例 8.15）：用 MOV 指令直接设置中断向量

**题干**：
设中断服务程序的入口地址名为 INTR_AD，类型号为 N，要求将 INTR_AD 的 CS:IP 置入 0000:（4×N）开始的单元中去，试编写汇编语言程序。

**解**：

第 1 步：确定地址关系。类型号为 N 的中断向量在中断向量表中的首地址为 $4 \times N$（向量表从 0000:0000 开始，每个向量占 4 字节）。其中偏移地址（IP 部分）存放在 $4 \times N$ 字单元，段基址（CS 部分）存放在 $4 \times N + 2$ 字单元。

第 2 步：设置目的段地址。向量表位于 0000 段，执行
```asm
MOV  AX, 0
MOV  ES, AX          ; 目的地址基址：ES=0000H
```
ES 指向中断向量表所在段。

第 3 步：设置目的偏移量。执行
```asm
MOV  BX, N*4         ; 目的地址偏移量：BX=4×N
```
BX 得到类型号 N 对应的向量在表内的偏移量 $4 \times N$。

第 4 步：取入口的偏移地址并写入。执行
```asm
MOV  AX, OFFSET INTR_AD
MOV  ES:[BX], AX     ; 置入偏移地址
```
把 INTR_AD 的偏移地址（OFFSET 分量）写入 0000:（4×N）字单元。

第 5 步：取入口的段基址并写入。执行
```asm
MOV  AX, SEG INTR_AD
MOV  ES:[BX+2], AX   ; 置入段基地址
```
把 INTR_AD 的段基址（SEG 分量）写入 0000:（4×N+2）字单元。

第 6 步：此后为中断服务程序本体，以 IRET 结束：
```asm
     ┆
INTR_AD:              ; 中断服务程序
     ┆
IRET
```

第 7 步：验证。写入完成后，中断向量表中类型号 N 对应表项的内容为：$(4 \times N)$ 单元 = OFFSET INTR_AD，$(4 \times N + 2)$ 单元 = SEG INTR_AD，即 CS:IP 恰为 INTR_AD 的入口地址，满足题干"将 INTR_AD 的 CS:IP 置入 0000:（4×N）开始的单元"的要求。服务程序入口地址由 OFFSET/SEG 两个伪指令给出，与题给条件完全对应。

**答案**：汇编程序如上（第 2~6 步完整程序段）。课件附注 TIP：这种方法并不安全，一般不建议采用。

### 例题 5（例 8.16）：利用 DOS 功能调用编写设置和取得中断向量的程序段

**题干**：
利用 DOS 功能调用，编写设置和取得中断向量的程序段。

**解**：

第 1 步：取得 N 号中断的原向量。执行
```asm
MOV  AL, N            ; 中断类型号N
MOV  AH, 35H
INT  21H              ; N号中断向量取到ES:BX
```
调用 35H 功能：AL=N 为类型号、AH=35H 为功能号。执行后原中断向量取到 ES:BX（ES=原向量的段基址，BX=原向量的偏移量）。

第 2 步：把原中断向量压入堆栈保存。执行
```asm
PUSH ES               ; 将原中断向量送堆栈保存
PUSH BX
```
先压段基址（ES 内容），后压偏移量（BX 内容）。此后栈顶往下依次为：原向量偏移量、原向量段基址、……。

第 3 步：保存 DS 原值。执行
```asm
PUSH DS               ; 保存DS
```
因为下一步 DS 要被改作新向量的段基址。

第 4 步：把新中断向量的段基址送 DS。执行
```asm
MOV  AX, SEG INTR_AD
MOV  DS, AX           ; DS←用户新中断向量段基址
```

第 5 步：把新中断向量的偏移量送 DX。执行
```asm
MOV  DX, OFFSET INTR_AD   ; DX←用户新中断向量偏移量
```
此时 DS:DX 恰好构成 25H 功能要求的入口参数格式（段基址在 DS，偏移量在 DX）。

第 6 步：设置新中断向量。执行
```asm
MOV  AL, N            ; 新中断向量类型号
MOV  AH, 25H
INT  21H              ; 设置新中断向量
```
调用 25H 功能，把 DS:DX（即 INTR_AD 入口）写入类型号 N 对应的表项。设置完成。

第 7 步：恢复 DS。执行
```asm
POP  DS               ; 恢复DS
```
弹出第 3 步压入的 DS 原值。

第 8 步：用户主程序运行（使用到该中断）：
```asm
     ┆                ; 用户的主程序，使用到该中断
```

第 9 步：恢复原中断向量。执行
```asm
POP  DX               ; 恢复原中断向量
POP  DS
```
弹栈次序与第 2 步压栈次序相反：先弹出的是原向量偏移量（原 BX 值）到 DX，后弹出的是原向量段基址（原 ES 值）到 DS。此时 DS:DX = 原中断向量。

第 10 步：用 25H 功能把原向量写回中断向量表。执行
```asm
MOV  AL, N
MOV  AH, 25H
INT  21H
RET
```
AL=N 为类型号、AH=25H 为功能号、DS:DX 为原向量，写回后向量表恢复程序运行前的状态。

第 11 步：中断服务程序本体（用户编写），以 IRET 结束：
```asm
INTR_AD
     ┆                ; 用户编写的中断服务程序
IRET
```

第 12 步：验证。程序开始时用 35H 功能读出原向量 ES:BX 并压栈保存；程序末尾按相反顺序弹出为 DS:DX，再用 25H 功能写回，写回值 = 读出值，向量表内容在程序结束后与开始时完全一致。程序运行期间类型号 N 指向新向量 INTR_AD（第 4~6 步写入），满足"设置和取得中断向量"的题干要求。其中 35H 的入口（AL=N、AH=35H）与 25H 的入口（AL=N、AH=25H、DS:DX=向量）均与课件第 37 页参数表一致。

**答案**：程序段如上（第 1~11 步），完成"取得原向量→保存→设置新向量→使用→恢复原向量"全过程。

### 例题 7（例 8.18）：编写中断处理程序——每隔 10 秒响铃一次并显示信息

**题干**：

编写中断处理程序，要求主程序运行时，每隔 10 秒钟响铃一次，并在 CRT 上显示一行信息 "The bell is ring."，主程序运行一定时间后停止运行。

分析：任务 1——显示信息——直接用 DOS 中断；任务 2——定时 10 秒——用 8253 定时中断；任务 3——响铃——控制扬声器（8253+8255）。

**解**：

第 1 步（确定定时节拍，第 42 页）：PC 机 8253 计数器 0 初始化为方式 3、二进制计数，初值 $n=0$（即 $2^{16}=65536$），输出频率 $f = 1.19318\,\mathrm{MHz}/65536 = 1193180/65536 \approx 18.2\,\mathrm{Hz}$，周期 $T = 1/18.2 \approx 55\,\mathrm{ms}$。OUT0 经 8259A IR0 引入 CPU，中断类型号为 1CH；原 1CH 服务程序只有一条 IRET。

第 2 步（确定响铃手段，第 43 页）：8253 计数器 2 方式 3，初值 $n=533\mathrm{H}=1331$，OUT2 频率 $= 1193180/1331 \approx 896\,\mathrm{Hz}$；GATE2 受 8255A PB0 控制（PB0=1 允许计数），扬声器受 PB1 控制（PB1=1 才能响），PB 口地址 61H。

第 3 步（确定 10 秒定时方案，第 44 页）：每次 1CH 中断将 COUNT 减 1；$55\,\mathrm{ms/次} \times 182\,\mathrm{次} = 10010\,\mathrm{ms} \approx 10\,\mathrm{s}$，即 182 次中断后时间到。COUNT=0 时响铃一次、显示信息、并重置 COUNT=182。

第 4 步（确定程序结构，第 44–45 页）：主程序依次完成中断初始化（取原向量→设新向量→开放 IR0→STI）、软件延时（期间发生中断）、延时完成后恢复原向量、退出程序；中断服务程序完成 COUNT 计数、响铃、显示、EOI、IRET。

第 11 步（用原始数据验证）：
- 定时验证：$55\,\mathrm{ms} \times 182 = 10010\,\mathrm{ms} \approx 10\,\mathrm{s}$，满足"每隔 10 秒响铃一次"；
- 首响验证：COUNT 首次值置 1，第一次进入服务程序时 $1 - 1 = 0$，立即响铃并显示一次，随后重置 COUNT=182，此后每 182 次中断（约 10 秒）响铃一次；
- 中断响应路径验证：IMR 的 D0 经 0FEH 与操作清 0，IR0 开放；STI 使 IF=1，CPU 允许响应；两条同时满足，定时中断可以进入 CPU；
- 向量恢复验证：先 PUSH ES、PUSH BX 保存，恢复时 POP DX（取回 BX 中的偏移量）、POP DS（取回 ES 中的段基址），重组为 DS:DX 后经 25H 功能写回，与保存时内容一致；
- 结束验证：EOI（20H 口输出 20H）通知 8259A 该级结束，IRET 恢复断点与标志，两条缺一不可。

**答案**：完整汇编程序由数据段（COUNT 首次值 1、显示信息字符串）、主程序（35H 取原向量→入栈保存→25H 设新向量→IMR 开放 IR0→STI→双重循环软件延时→恢复原向量→4C00H 返回 DOS）与中断服务程序 RING（保护现场→STI→COUNT 递减判断→09H 功能显示信息→61H 口控制扬声器通断 100 次→COUNT 重置 182→EOI→恢复现场→IRET）构成，实现主程序运行期间每约 10 秒响铃一次并显示 "The bell is ring."。

### 例题 8（思考题）：要求响铃 10 次后结束程序

**题干**：

如果要求响铃 10 次结束程序，程序怎么改？（5 分钟思考时间，给出解决方案。）

**解**：

第 1 步（分析原程序缺陷）：原程序中主程序软件延时（约 >10 秒）一结束就立即恢复原中断向量并退出。若延时结束时刻响铃不足 10 次，其余响铃将不再发生，因此需要在响铃次数与程序退出之间建立同步。

第 2 步（参考方案总体思路，第 53 页）：定义一个变量 count0，初始化值为 10；每响铃一次减 1；主程序延时结束后判断 count0 是否为 0，已经响铃 10 次后才退出主循环的延时等待。

第 3 步（修改数据段，第 53 页，绿色代码部分）：

```asm
DATA       SEGMENT              ；数据段
COUNT      DW    1              ；10s计数器首次值置为1
count0     DB    10             ；新增：响铃次数计数器，初值10
MESS       DB    'The bell is ring.'，0AH，0DH，'$'    ；要显示的信息
DATA       ENDS
;主程序
CODE       SEGMENT
           ASSUME  CS:CODE，DS:DATA
START:
    MOV    AX，DATA             ；设置数据段
    MOV    DS，AX
;;;;;取出原中断向量，入栈保存;;;;;
    MOV    AL，1CH              ；指向1CH号中断向量
    MOV    AH，35H              ；取1CH号中断向量
    INT    21H                  ；ES：BX←中断向量
    PUSH   ES
    PUSH   BX                   ；1CH中断向量入栈保护
```

第 4 步（设置新中断向量并开中断，第 54 页，与例题 7 相同未改动）：

```asm
;;;;;设置新的中断向量;;;;;
    PUSH   DS                   ；保存DS
    MOV    DX，OFFSET RING      ；DS：DX←RING的基地址和偏移量
    MOV    AX，SEG RING
    MOV    DS，AX
    MOV    AL，1CH              ；RING的中断类型号
    MOV    AH，25H
    INT    21H                  ；设置RING的中断向量
    POP    DS                   ；恢复DS
;;;;;允许IR0中断请求，开中断;;;;;
    IN     AL，21H              ；读IMR
    AND    AL，0FEH             ；使IMR的D0位=0，以允许IR0中断
    OUT    21H，AL
    STI                         ；开中断，等待定时中断
```

第 5 步（主程序延时后增加等待循环，第 55 页，绿色代码部分）：

```asm
;;;;;软件延时，期间有中断产生;;;;;
    MOV    DI，20000            ；延时一定时间(>10s)
DELY:
    MOV    SI，30000
DELY1:
    DEC    SI
    JNZ    DELY1
    DEC    DI
    JNZ    DELY
WAIT0:
    cmp    count0,0             ；如果最后一次响铃还没有完成
    JNZ    WAIT0                ；count0≠0则继续等待
;;;;;恢复旧的中断向量，主程序结束;;;;;
    POP    DX                   ；时间到，原中断向量弹出到DS：DX中
    POP    DS
    MOV    AL，1CH              ；中断类型号
    MOV    AH，25H              ；恢复原中断向量
    INT    21H
    MOV    AX，4C00H            ；返回DOS
    INT    21H                  ；主程序结束
```

第 6 步（服务程序改为 NEAR 并加入 dec count0，第 56 页，绿色代码部分）：

```asm
;中断服务程序RING
RING  PROC  NEAR
    ;;;;;现场保护，开中断;;;;;
    PUSH   DS                   ；保护现场
    PUSH   AX
    PUSH   CX
    PUSH   DX
    MOV    AX，DATA             ；设置数据段
    MOV    DS，AX
    STI                         ；开中断，允许中断嵌套
    ;;;;;10s定时判断;;;;;
    DEC    COUNT                ；10s计数器COUNT（初始值=1）
    JNZ    EXIT                 ；非0，10s时间未到，则退出
    ;;;;;定时时间到，显示信息;;;;;
    dec    count0               ；新增：响铃次数减1
    MOV    DX，OFFSET MESS      ；是0，10s到，显示提示信息
    MOV    AH，09H
    INT    21H
```

第 7 步（响铃与 EOI，第 57 页，与例题 7 相同）：

```asm
    ;;;;;控制扬声器;;;;;
    MOV    DX，100              ；扬声器通断100次
    IN     AL，61H              ；8255A的PB端口地址
    AND    AL，0FCH             ；使8255A的PB1PB0=00
SOUND:
    XOR    AL，02H              ；61H口的D1位，PB1取反
    OUT    61H，AL              ；由1→0，由0→1
    MOV    CX，140H             ；延时使方波有一定宽度
WAIT1:
    LOOP   WAIT1
    DEC    DX                   ；通断100次了吗？
    JNE    SOUND                ；没有，继续发声
    ;;;;;重置10s定时器COUNT;;;;;
    MOV    COUNT，182           ；重置COUNT←182
    ;;;;;用8259的EOI命令结束中断;;;;;
EXIT:
    MOV    AL，20H              ；用EOI命令结束中断
    OUT    20H，AL
```

第 8 步（恢复现场与返回，第 58 页，与例题 7 相同）：

```asm
    ;;;;;现场恢复;;;;;
    POP    DX                   ；恢复现场
    POP    CX
    POP    AX
    POP    DS
    ;;;;;退出中断服务;;;;;
    IRET                        ；返回主程序，等待下次中断
RING  ENDP                      ；中断服务程序结束
CODE  ENDS                      ；代码段结束
      END    START              ；程序将从START执行
```

第 9 步（用原始数据验证）：
- 计数验证：count0 初值 10，每 10 秒时间到执行一次 dec count0，第 10 次响铃后 $10-10=0$；
- 同步验证：主程序延时结束后进入 WAIT0，`cmp count0,0` 比较，只要 count0≠0 就 JNZ 回到 WAIT0 继续等待；等待期间中断照常发生，服务程序继续响铃并递减 count0，直到 count0=0 才顺序执行恢复原向量与返回 DOS；
- 时序验证：COUNT 首次置 1，第一次进入服务程序（约 55 ms 后）即完成第 1 次响铃（count0 变 9），此后每 $55\,\mathrm{ms} \times 182 = 10010\,\mathrm{ms} \approx 10\,\mathrm{s}$ 响铃一次，10 次响铃约在 $55\,\mathrm{ms} + 9 \times 10\,\mathrm{s} \approx 90\,\mathrm{s}$ 处全部完成，程序随之退出。

**答案**：共三处修改——数据段增加 `count0 DB 10`；中断服务程序在 10 秒时间到、显示信息处增加 `dec count0`；主程序软件延时结束后增加 `WAIT0: cmp count0,0 / JNZ WAIT0` 等待循环。响铃满 10 次（count0=0）后恢复原 1CH 中断向量并返回 DOS。
