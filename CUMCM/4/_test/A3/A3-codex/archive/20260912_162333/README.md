# A3-codex：第三问建模与完整交付

先阅读 **建模报告.md**。题目要求的提交表格是 **result3.xlsx**，表5另见 **表5.md**。

在承接第二问的显热、有效Robin边界模型，并假设4小时后环境保持末值的条件下：

- 连续临界时刻：57.169466 h，此时最大含水率等于0.15。
- 首次严格达标整分钟：57小时11分钟，即57.1833 h、205860 s。
- 工作簿3431条时间记录 × 21个半径值，含水率保留四位小数。
- 含水率工程数值误差估计1.771×10⁻⁶ kg/kg；800与1600单元临界时间差0.239 s。

这些是指定模型下的数值结果，不是实测预测误差保证。严格达标按未舍入值判定，Excel末行中心显示0.1500并不代表未达标。环境外推、气固平衡闭合和显热近似详见报告。

## 复现

科学计算需要Python 3.13、NumPy、SciPy、Numba、Matplotlib、openpyxl；openpyxl仅用于读和核验工作簿。测试版本见requirements.txt。保持本目录在`A3/A3-codex`，并保留上级原题模板和第二问tight800基准文件。

本机执行：

```bash
OPENBLAS_NUM_THREADS=1 /opt/anaconda3/bin/python code/run_all.py --recompute
```

其他计算机可将解释器改为已安装依赖的`python`。一键命令重新计算全部十个算例，再生成报告、图像、Excel并回读检查，通常需要数分钟。运行过程会覆盖本目录内的同名派生文件，不修改原题或其他方案。

```bash
python code/run_all.py --math-only   # 计算、验证、报告和图像，不导出Excel
python code/produce.py             # 仅用已有完整算例重新整理报告和图像
python code/check_workbook.py      # 仅回读已生成Excel
```

默认缓存仅在算例参数及core.py、solve.py、ambient.csv的SHA-256完全匹配时复用；未登记缓存会重算。`--recompute`强制重新计算。若改变数学模型，也应同步更新报告模板中的模型说明，不能只重算数字。

Excel由Codex自带Node与`@oai/artifact-tool`生成。`run_all.py`自动使用本机Codex运行时，或通过`A3_NODE`和`A3_NODE_MODULES`指定对应Node可执行文件与包目录。`code/node_modules`只是本机链接，不是算法依赖数据。没有该包时，`--math-only`仍可复现所有数学结果；已交付的Excel可直接使用。

## 检查范围

- 400/800/1600单元空间收敛、800单元积分容差收敛、400单元Radau时间算法对照。
- 前3小时与第二问的60 s采样结果核对；独立向量算子与非线性表面求根复核最终和合成状态。
- 实际边界通量Gauss时间积分、水分收支与带变热容链式修正的显热诊断收支。
- 首次达标分钟前后的未舍入全场最大值、各输出时刻单元径向顺序、数值量程。
- 5种环境外推情景，与同网格基准比较；未将其误称为统计置信区间。
- Excel全部72051个含水率数字、3431个时间值、21个半径、四位小数格式、表5、冻结窗格回读。

第二问代码来源记录于data/source_sha256.json。主空间内核继承第二问；Radau复用空间算子，独立算子审计只验证选定状态，均不应夸大为独立完整物理验证。原A3-ds的疑点与结论差异在报告中逐项说明。
