## 3. 【P0】失水量超出表面可获得能量的约 12 倍

### 3.1 核算（只用交付数据本身与题给参数）

脚本 `code/audit_energy.py` → `verification/energy_audit.json`。全部输入为交付的 `T`、`C`、`means` 数组与题给的 `h = 25 W/(m²·K)`，**不含审核方的任何模型**。

| 量 | 数值 |
|---|---:|
| 表面与环境温差最大值 | 6.19 K（t≈1860 s，T_a=41.92 ℃） |
| 3 h 内穿过表面进入药材的能量 `∫h(T_a−T_s)·2πR dt` | **8.38e4 J/m** |
| 其中用于显热升温（交付的均温由 28 升到 49.90 ℃） | 6.91e4 J/m |
| **留给蒸发相变的能量**（上两者之差） | **1.47e4 J/m** |
| 交付的水分场排出的水量 `ρ_d ΔC̄ πR²` | **0.40351 kg/m** |
| 蒸发这些水所需潜热（L_v = 2.40e6 J/kg） | **9.674e5 J/m** |
| **潜热 / 可供相变的能量** | **66 倍** |
| **潜热 / 进入药材的全部能量** | **11.5 倍** |
| 按可供相变的能量，最多能蒸发的水 | 0.00610 kg/m |
| 对应的最大平均降湿 | 0.0177 kg/kg（交付为 **1.1675**） |

**即：交付模型的表面在整个 3 h 内只吸收了约 84 kJ/m 的热量，却排出了需要 967 kJ/m 才能蒸发的 0.40 kg/m 水——相差约 12 倍（只看相变能量则相差 66 倍）。**

### 3.2 原因：表面能量平衡缺潜热汇

代码的表面热边界只有显热项：

$$-k\,\partial_rT\big|_R=h\,(T_s-T_a),\qquad \text{缺}\quad +\,L_v(T_s)\,j_R.$$

模型的水分方程却在持续失水。两者独立推进、互不结算，于是出现"蒸发没有热源的水"。这也解释了为什么表 3 的表面温度在 3 h 末达到 49.9664 ℃、几乎等于环境温度——表面没有任何吸热机制。

### 3.3 影响方向

补上潜热汇后：

1. 表面被冷却，`T_s < T_a`；
2. 表面与环境温差拉大 → 对流供热增加，但仍受 `h` 限制；
3. 表面温度下降 → 水分边界驱动势下降 → 失水变慢；
4. 三者自洽后，**表 3 的温度需下调、表 4 的含水率需上调**，且幅度不是末位修正（可供能量只够支持交付失水量的约 1/12）。

**注意**：本条只证明"不相容"，不给出修正后的具体数值——正确数值需要把潜热项与实际水分边界条件耦合求解后重新积分。

### 3.4 修改办法

1. 表面热边界补 $L_v(T_s)\,j_R$，$L_v(T)=2.501\times10^6-2.361\times10^3\,T$（℃）；
2. 表面重构的定点迭代把它一起解（本次数值试验显示该迭代强收缩，2—3 次即收敛）；
3. **新增能量收支审计**（与现有质量收支并列）：逐秒累计
   `∫h(T_a−T_s)2πR dt`、`∫L_v j_R 2πR dt`、`Δ(显热储)`，三者必须闭合。
   现有 `verification/balance.csv` 只有质量一项，**正是这一缺失让问题长期未被发现**；
4. **不要以"题目未给 L_v"为由省略**：`L_v` 是水的已知物性（≈2.4e6 J/kg），不属不可辨识参数。若坚持显热近似，必须给出"潜热 ≪ 显热"的定量证明——本次核算给出的是相反结论。

## 4. 【P1】水分边界条件的量纲与外部传热不相容

### 4.1 量纲

代码用

$$j_R=h_m\,(C_s-C_a),\qquad h_m=8\times10^{-7}\ \text{m/s}.$$

`h_m` 的单位是 **m/s（速度）**，属**气相**传质系数；而 `C` 是**干基含水率 kg/kg（干料）**。"速度 × 质量分数"得不到 kg/(m²·s)。量纲一致的写法应为

$$j_R=h_m\,\rho_d\,(C_s-C_a)\qquad\text{或}\qquad j_R=h_m\,\rho_a\big(Y_{sat}(T_s)-Y_a\big),$$

其中 `ρ_d = ρ(C₀)/(1+C₀) = 275.04 kg/m³` 已由代码自身的水分方程隐含（该方程正是以 `ρ_d` 为常数写的）。

### 4.2 为什么代码仍然"质量守恒"

脚本 `code/audit_conservation.py`：代码写下的通量在整个 3 h 的积分是 1.467e-03 kg/m，而交付的体积平均失水是 0.4035 kg/m，两者之比恰为 **275.04 = ρ_d**。这说明：

- 离散格式排出的水量，精确等于"带 `ρ_d` 的正确公式"所能给出的水量；
- 代码写下的公式本身解释不了这个水量，**它是靠内部浓度梯度而不是靠 Robin 条件把水排出去的**；
- 由于两侧同用一个公式，`analyze.py` 的质量收支检查两边同错、残差自然到机器精度，**发现不了这个量纲问题**。

因此该边界条件对结果的**定量**影响，取决于 Robin 条件能把表面浓度钉在多低（见 §4.3），而不是一个固定的倍数。

### 4.3 与外部传热的相容性

把给定 `h_m` 当作气相速度使用（`j = h_m ρ_a (Y_sat(T_s)−Y_a)`）：

| 量 | 数值 |
|---|---:|
| 3 h 的气侧传质上限 | 2.75e-05 kg/m |
| 交付的失水 | 0.4035 kg/m |
| 比值 | 约 14700 |

同时，按 §3 的能量约束上限是 0.0061 kg/m。两条独立途径都表明：**在题目给定的 `h` 与 `h_m` 下，3 h 能排出的水量比交付值小 2—4 个数量级**。

独立的对照算例（`verification/uni_latent_n200_p1.0.npz`，均匀网格 N=200，湿度比驱动 + 潜热汇）给出：3 h 末中心含水率 2.535、平均含水率 2.523、平均温度 28.4 ℃，平均降湿仅 **0.027 kg/kg**。该算例依赖一个题目未给的吸附等温线参数，因此只作**定性**参考，不作数值结论；但它与 §3 的能量上限方向一致。

### 4.4 修改办法

1. 把质流边界改为量纲一致的湿度比/蒸汽压形式
   $$j_R=h_m\,\rho_a\big[\,a_w\,Y_{sat}(T_s)-Y_a\,\big],\qquad
   Y=\frac{0.621945\,p_{sat}}{P-p_{sat}},\quad
   p_{sat}=\text{ASHRAE 饱和水汽压};$$
   `a_w` 取 1（表面仍由内部供水维持湿润）或按吸附等温线取 `a_w=exp(−X₀/C_s)`；
2. **给出两套闭合的对照**（"表面饱和"与"等温线"），量化该假设对表 3/表 4 的影响——题目没给等温线，对照本身就是评分点；
3. 论文中明确写出 `C_a` 的量纲是 kg/kg 干空气，并说明如何换算到干基含水率。

## 5. 数值鲁棒性建议

### 5.1 最外层单元过度刚硬

二次聚簇 `r_j=R[1−(1−j/N)²]` 使最外单元厚度随 N 急剧收缩（`code/diag_mesh.py`）：

| N | 最外单元厚/m | 半单元 δ/m | 表面单元时间常数 δ²/D | 单元尺寸比 |
|---:|---:|---:|---:|---:|
| 200 | 5.00e-07 | 2.50e-07 | 1.1e-05 s | 3.99e2 |
| 400 | 1.25e-07 | 6.25e-08 | 6.9e-07 s | 7.99e2 |
| 800 | 3.13e-08 | 1.56e-08 | 4.3e-08 s | 1.60e3 |
| 1600 | 7.81e-09 | 3.91e-09 | 2.7e-09 s | 3.20e3 |

最外节点 Jacobian 元素达 1e6 量级，内层为 1e-3 量级，**刚度比 >1e12**。可复现的后果（`code/diag_stability.py`，用原始模块）：

```
n=400, rtol=1e-9,  max_step=10 : 最外单元含水率 60 s 内崩到 0.092，此后全场失真
n=800, rtol=1e-9,  max_step=10 : 同样崩到 0.078
n=800, rtol=1e-11（交付设置）  : 输出平滑合理，且可被逐位复现
```

即交付解是**特定容差组合下才稳定**的轨迹。`verification/` 里同时保留了 `base200/base400/base800`（rtol=1e-9）与 `tight800/tight1600`（rtol=1e-11）两种容差，二者物理结论不同，**可复算性与可比性差**。
建议改为**内层均匀、外层等比加密**的混合网格（或给最外单元厚度设 `√(D·Δt_min)` 下界），并重做网格收敛序列。

## 7. 给作者的最小改动清单

```python
# A2-gpt/code/solver.py
RHO_D = (650. + 128.*2.55) / (1. + 2.55)          # 275.04 kg/m3

@njit(cache=True)
def boundary(t, c, ta, ca, half, q1, h, hm, df):
    ts, cs = t, c
    for it in range(60):
        k, d = face(t, c, ts, cs, q1, df)
        tn = (k*t + h*half*ta) / (k + h*half)
        cn = (d*c + hm*RHO_D*half*ca) / (d + hm*RHO_D*half)   # 补 rho_d
        Lv = 2.501e6 - 2.361e3*tn
        j  = hm*RHO_D*(cn - ca)
        tn = tn - half*Lv*j/(k + h*half)                      # 补潜热汇
        err = max(abs(tn-ts), abs(cn-cs))
        ts, cs = tn, cn
        if err < 2e-13:
            return ts, cs, h*(ts-ta) + Lv*j, j
    raise ValueError('Surface iteration failed')
```
